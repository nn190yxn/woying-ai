# 数据模型

## 数据层入口

后端通过 `backend/src/models/db.js` 暴露 `query()` 和 `getConnection()`。运行时优先连接 MySQL，连接失败时在非生产环境降级到 `backend/src/models/mockDb.js` 的内存模拟数据层。生产环境查询失败会抛错，避免线上写入静默落入 mock。

`initDB()` 当前负责初始化业务新增表：`user_sheets`、`douyin_quick_plans`、`douyin_review_records`。其他表由既有数据库迁移或线上库结构承载，代码通过查询语句消费这些表。

`douyin_quick_plans` 保存当前用户最近一份抖音 15 天计划，包含 `plan_version` 和 `input_hash`。保存接口写入当前 QuickPlanResult 版本和标准输入摘要，读取接口会迁移旧计划并在 `plan.meta.migrated` 标记迁移状态。

日任务状态更新会写回迁移后的完整 `plan` JSON，并同步保留 `plan_version` 与 `input_hash`。

## 用户与会员

### users

用户主表，支撑注册、登录、会员权限、推荐关系和后台用户管理。

已确认字段来自 `auth.js`、`user.js`、`payment.js`、`referral.js` 和 `admin.js`：

- `id`：用户主键，JWT 中使用 `userId`。
- `phone`：手机号，注册和登录使用。
- `password_hash`：注册时写入的密码哈希。
- `nickname`：用户昵称。
- `member_level`：会员等级，常见值包括 `free`、`starter`、`pro`、`annual`。
- `member_expire_at`：会员到期时间，支付成功后按套餐周期累加。
- `industry`、`city`：用户资料页维护的行业和城市。
- `referral_code`：用户邀请码。
- `referred_by`：推荐人用户 ID。
- `referral_bonus_days`：推荐奖励天数累计。
- `created_at`：注册时间。

关键写入路径：

- `/api/auth/register` 创建用户并写入 `referral_code`。
- `/api/payment/callback` 在支付成功后更新 `member_level` 和 `member_expire_at`。
- `/api/user/profile` 更新 `nickname`、`industry`、`city`。
- 推荐返利工具会更新 `referral_bonus_days` 和会员有效期。

## 订单与返利

### orders

订单表，支撑会员购买、支付回调、订单查询和返利计算。

已确认字段：

- `id`：订单主键。
- `user_id`：下单用户。
- `plan_code`：套餐代码，对应 `starter`、`pro`、`annual`。
- `plan_name`：套餐展示名。
- `amount`：订单金额，后端价格权威来源为 `backend/src/config/plans.js`。
- `status`：订单状态，支付回调接受 `pending`、`paid`、`failed`。
- `paid_at`：支付完成时间。
- `created_at`：创建时间。

支付成功时会用事务和行锁读取订单，更新订单状态，再累加用户会员有效期。返利计算在主事务完成后执行，避免返利失败影响支付主链路。

### referral_commissions

推荐佣金表，后台和推荐工具读取并更新该表。

已确认字段来自查询路径：

- `id`：佣金记录主键。
- `referrer_user_id`：推荐人。
- `buyer_user_id`：购买用户。
- `order_id`：关联订单。
- `commission_amount`：佣金金额。
- `status`：佣金状态。
- `settled_at`：结算时间。
- `created_at`：创建时间。

## 工具使用与结果

### tool_usage

工具使用流水表，用于限制免费用户用量、后台统计和工具运行记录。

已确认字段：

- `id`：流水主键。
- `user_id`：用户 ID。
- `tool_code`：工具代码。
- `created_at`：调用时间。

关键读取路径包括 `/api/tools/check-access`、`/api/tools/use`、`/api/generate/:toolCode` 和后台工具统计。

### tool_results

工具结果表，用于保存通用工具输入输出，支持用户历史记录查询。

已确认字段：

- `id`：结果主键。
- `user_id`：用户 ID。
- `tool_code`：工具代码。
- `input_json`：用户输入。
- `output_json`：工具输出。
- `created_at`：生成时间。

## 经营体检与表格

### diagnosis_reports

体检报告表，用于保存诊断问卷输入和分析结果。

已确认字段：

- `id`：报告主键。
- `user_id`：用户 ID。
- `answers_json`：诊断输入。
- `analysis_json`：诊断输出。
- `created_at`：创建时间。

### user_sheets

用户表格保存表，由 `initDB()` 初始化。

```sql
CREATE TABLE IF NOT EXISTS user_sheets (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id VARCHAR(64) NOT NULL,
  sheet_code VARCHAR(128) NOT NULL,
  sheet_data JSON,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE INDEX idx_user_sheet (user_id, sheet_code)
)
```

业务含义：同一用户同一 `sheet_code` 只保留一份最新表格数据，`/api/sheets/save` 使用 `ON DUPLICATE KEY UPDATE` 覆盖更新。

## 抖音经营闭环

### douyin_quick_plans

抖音 15 天作战计划保存表，由 `initDB()` 初始化。

```sql
CREATE TABLE IF NOT EXISTS douyin_quick_plans (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id VARCHAR(64) NOT NULL,
  industry VARCHAR(64) NOT NULL,
  goal VARCHAR(64) NOT NULL,
  frequency VARCHAR(16) NOT NULL,
  ad_support VARCHAR(32) NOT NULL,
  diagnosis_context JSON,
  plan JSON NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE INDEX idx_user_douyin_quick_plan (user_id)
)
```

业务含义：同一用户保存最近一份作战计划。生成新计划、手动保存计划和每日任务状态更新都会落到这张表。

主要接口：

- `GET /api/douyin/quick-plan/saved`：读取当前用户已保存计划。
- `POST /api/douyin/quick-plan/save`：保存当前计划。
- `PATCH /api/douyin/quick-plan/tasks/:day`：更新指定天任务状态。

### douyin_review_records

抖音数据复盘记录表，由 `initDB()` 初始化。

```sql
CREATE TABLE IF NOT EXISTS douyin_review_records (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id VARCHAR(64) NOT NULL,
  industry VARCHAR(64),
  goal VARCHAR(64),
  source_context JSON,
  input_data JSON NOT NULL,
  result_data JSON NOT NULL,
  effective_content_types JSON,
  next_actions JSON,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_douyin_review_created (user_id, created_at)
)
```

业务含义：同一用户保留多条复盘记录，支持最近复盘恢复和基于最近记录的趋势洞察。

主要接口：

- `GET /api/douyin/review-records/latest`：读取最近一条复盘。
- `GET /api/douyin/review-records`：读取复盘列表。
- `POST /api/douyin/review-records`：保存复盘输入、诊断结果和下一步行动。
- `GET /api/douyin/review-records/insights`：聚合最近 20 条复盘记录，输出有效内容类型和下一轮计划建议。

## 运营与反馈

### user_feedbacks

用户反馈表，支撑用户提交反馈和后台处理。

已确认字段：

- `id`：反馈主键。
- `user_id`：提交用户。
- `type`：反馈类型。
- `title`：标题。
- `description`：描述。
- `image_url`：图片地址。
- `status`：处理状态。
- `admin_note`：后台备注。
- `created_at`、`updated_at`：时间字段。

### analytics_events

行为事件表，schema 定义在 `backend/src/services/analytics.js`。

```sql
CREATE TABLE IF NOT EXISTS analytics_events (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NULL,
  event_type VARCHAR(50) NOT NULL,
  event_meta JSON NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_event (user_id, event_type),
  INDEX idx_event_type (event_type),
  INDEX idx_created_at (created_at),
  INDEX idx_event_tool (event_type, (JSON_EXTRACT(event_meta, '$.toolCode')))
)
```

主要事件类型包括工具浏览、工具提交、工具成功、工具失败、会员升级、注册、登录和支付结果。

## 本地 mock 数据层

`backend/src/models/mockDb.js` 覆盖以下表的核心读写：

- `users`
- `orders`
- `tool_usage`
- `tool_results`
- `diagnosis_reports`
- `douyin_quick_plans`
- `douyin_review_records`

mock 层用于本地 MySQL 不可用时继续开发和测试。生产环境查询失败会抛错，线上验收应以真实 MySQL 为准。
