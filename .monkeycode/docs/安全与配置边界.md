# 安全与配置边界

## 配置原则

项目配置以环境变量为主，代码和文档只保留变量名、默认值语义和占位符。真实密钥、数据库密码、JWT 密钥、支付密钥、私钥和 AI Key 保留在运行环境中。

## 鉴权边界

通用鉴权由 `backend/src/middleware/auth.js` 提供：

- `JWT_SECRET` 是生产环境必需配置。
- `authMiddleware` 从 `Authorization: Bearer <token>` 读取 JWT。
- 鉴权失败返回 401。
- `optionalAuth` 允许有 token 时附加用户信息。

非生产环境默认启用 guest mode，`req.user` 会被设置为年费等级访客，便于本地调试。设置 `GUEST_MODE=false` 可关闭 guest mode。

生产环境必须保持 `NODE_ENV=production`，并配置强随机 `JWT_SECRET`。

## 会员权限边界

会员等级顺序：

- `free`
- `starter`
- `pro`
- `annual`

权限判断分布在三层：

- 前端入口展示和路由提示：`frontend/src/constants/membership.js`。
- 通用工具后端权限：`backend/src/config/toolAccess.js`。
- 专项路由权限：抖音、小红书、私域路由中的 `requireLevel()`。

权限调整时需同步检查三层，避免前端显示、后端访问和工具配额出现不一致。

## AI Key 配置

项目侧 AI 配置使用：

- `USER_LLM_API_KEY`
- `USER_LLM_BASE_URL`
- `USER_LLM_MODEL`
- `AI_REQUEST_TIMEOUT`

`backend/src/services/ai.js` 当前会按 Chat Completions 协议请求 `{BASE_URL}/chat/completions`。新增 AI 能力时应继续使用项目侧 `USER_LLM_*` 变量，并在示例配置中使用占位符。

文档、日志、测试报告和前端页面中严禁输出真实 AI Key。

## 数据库配置

数据库变量：

- `DB_HOST` 或 `MYSQL_HOST`
- `DB_PORT` 或 `MYSQL_PORT`
- `DB_NAME` 或 `MYSQL_DATABASE`
- `DB_USER` 或 `MYSQL_USER`
- `DB_PASSWORD` 或 `MYSQL_PASSWORD`

生产环境查询失败会抛错。本地开发连接失败时会落到内存 mock DB，该行为适合开发和测试，线上验收应确认真实 MySQL 正常写入。

涉及用户隔离的数据表应始终带 `user_id` 查询条件，包括工具结果、表格、抖音计划和复盘记录。

## Redis 与验证码

Redis 配置：

- `USE_REAL_REDIS=true`
- `REDIS_URL` 或 `REDIS_HOST`

默认使用内存 mock Redis。验证码 key 为 `code:<phone>`，有效期 300 秒。`INTERNAL_TEST_VERIFICATION_CODE` 只适合内测，正式公开发布前应清空。

## 支付回调

支付回调由 `backend/src/routes/payment.js` 处理。

关键边界：

- `PAYMENT_CALLBACK_SECRET` 必须配置。
- 签名 payload 为 `orderId:status`。
- 签名算法为 HMAC SHA-256。
- 回调状态只接受 `paid`、`failed`、`pending`。
- 回调时间戳如果存在，必须在 5 分钟窗口内。
- 支付成功使用事务和 `FOR UPDATE` 保护订单幂等。

支付成功后，订单状态更新和会员有效期累加在同一事务中完成。推荐佣金在主事务后执行，返利失败会写日志。

## 内容安全接口

内容安全接口位于 `backend/src/routes/security.js`：

- `POST /api/security/check-text`
- `POST /api/security/check-image`

当前文本接口执行基础敏感词过滤，图片接口返回通过。代码中保留接入微信或腾讯云审核的 TODO。对外发布审核强相关场景时，应接入正式内容安全服务。

## Token Monitor 暴露面

`backend/src/routes/tokenMonitor.js` 提供 token 用量统计、价格参考和 dashboard 数据接口，当前路由在 `backend/src/index.js` 中直接挂载为 `/api/token-monitor`。

这些接口可读取模型用量统计和质量反馈摘要。生产环境建议纳入管理员鉴权或反向代理访问控制，并避免在公开页面暴露。

## 日志与敏感信息

日志系统位于 `backend/src/middleware/logger.js`，默认写入 `logs/`：

- `request.log`
- `error.log`
- `audit.log`

工具执行日志记录 input keys、toolCode、userId 和错误消息。新增日志时应记录定位所需的字段名和状态，避免写入完整用户输入、密钥、token、支付签名或私钥内容。

## CORS 与请求体

Express 当前启用全局 `cors()`，并设置 JSON 请求体大小限制为 `1mb`。

公开生产环境如需更严格边界，可在网关或 Express 层限制允许来源、请求方法和请求头，并为大文件上传走独立通道。

## 部署密钥边界

服务器 SSH 私钥只用于部署连接和文件传输。文档、日志、终端输出和项目文件中严禁展示或复制私钥内容。

线上目录通常不是 Git 仓库，部署通过备份包和最小覆盖文件完成。上线前保留备份包，回滚时使用备份包恢复运行文件。

## 发布前安全检查

发布前建议检查：

- `NODE_ENV=production`。
- `JWT_SECRET` 已配置且强度足够。
- `PAYMENT_CALLBACK_SECRET` 已配置。
- `INTERNAL_TEST_VERIFICATION_CODE` 已按发布阶段处理。
- `USER_LLM_*` 已配置在运行环境内。
- 数据库连接使用真实 MySQL。
- token monitor 已受控访问。
- 文档和代码中无真实密钥。
- 新增接口已具备鉴权、会员权限和用户隔离。
