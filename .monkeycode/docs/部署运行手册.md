# 部署运行手册

## 运行组件

我赢AI当前运行形态包含前端静态资源、Express 后端、MySQL、Redis、AI 网关配置和 PM2 进程管理。

线上已确认信息：

- 主站地址：`https://woyai.cn/`
- 健康检查：`https://woyai.cn/api/health`
- 线上项目目录：`/home/ubuntu/woying-ai`
- 线上后端目录：`/home/ubuntu/woying-ai/backend`
- 线上 PM2 服务名：`woying-backend`
- 本地仓库目录：`/workspace/woying-ai`

## 本地构建

前端构建命令：

```bash
cd frontend
npm run build
```

后端为 Node.js ESM 服务，没有编译产物。上线前至少执行语法检查：

```bash
cd backend
node --check src/index.js
```

本轮涉及抖音经营闭环时，还应检查核心改动文件：

```bash
cd backend
node --check src/routes/douyinAgents.js
node --check src/models/db.js
node --check src/models/mockDb.js
```

## 环境变量

后端通过 `dotenv` 读取运行环境配置，关键变量包括：

- `PORT`：后端监听端口，默认 `3001`。
- `JWT_SECRET`：JWT 签名密钥，生产环境必填。
- `JWT_EXPIRES_IN`：登录有效期，默认 `7d`。
- `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`：MySQL 连接配置。
- `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`：MySQL 兼容变量。
- `PAYMENT_CALLBACK_SECRET`：支付回调签名密钥。
- `USER_LLM_API_KEY`、`USER_LLM_BASE_URL`、`USER_LLM_MODEL`：项目自身 AI 能力配置。
- `INTERNAL_TEST_VERIFICATION_CODE`：内测验证码，仅用于受控测试。

文档和示例中只写变量名和占位符，真实值保留在线上环境配置内。

## 部署前检查

部署前应确认：

- 本地 `frontend/dist` 来自最新 `npm run build`。
- 后端改动文件已通过 `node --check`。
- 数据表初始化逻辑已覆盖新增持久化表。
- 新接口具备鉴权、权限等级和用户隔离。
- 线上目录结构与待覆盖文件路径一致。
- 线上部署前已创建可回滚备份。

## 备份策略

线上目录通常不是 Git 仓库，部署前必须把即将覆盖的运行文件打包备份。

本轮使用过的备份方式：

```bash
# 在服务器创建备份目录
mkdir -p /home/ubuntu/woying-ai-backups/<timestamp>

# 备份前端 dist 和目标后端文件
tar -czf /home/ubuntu/woying-ai-backups/<timestamp>/runtime-before-change.tgz \
  -C /home/ubuntu/woying-ai \
  frontend/dist \
  backend/src/routes/douyinAgents.js \
  backend/src/models/db.js \
  backend/src/models/mockDb.js
```

备份包命名应体现时间和变更批次，便于回滚时定位。

## 同步策略

当前环境本地和线上都可能缺少 `rsync`，可使用 `tar` 作为最小部署包。部署包只包含本轮确认要覆盖的文件，降低线上变更面。

推荐结构：

```text
deploy-package/
  frontend/dist/
  backend/src/routes/douyinAgents.js
  backend/src/models/db.js
  backend/src/models/mockDb.js
```

上传后在服务器项目根目录解包覆盖：

```bash
tar -xzf /home/ubuntu/woying-ai-backups/<timestamp>/deploy-change.tgz -C /home/ubuntu/woying-ai
```

## 重启后端

后端通过 PM2 管理，部署后重启服务：

```bash
pm2 restart woying-backend
pm2 status woying-backend
```

PM2 状态应为 `online`。如状态异常，先查看 PM2 日志和后端启动日志，再执行回滚。

## 健康检查

后端提供两个健康检查端点：

- `GET /health`
- `GET /api/health`

线上验收使用：

```bash
curl -fsS https://woyai.cn/api/health
```

期望返回包含 `status: ok` 的 JSON。

## 回滚路径

如部署后出现启动失败、核心接口失败或前端资源异常，按备份包回滚：

```bash
tar -xzf /home/ubuntu/woying-ai-backups/<timestamp>/runtime-before-change.tgz -C /home/ubuntu/woying-ai
pm2 restart woying-backend
```

回滚后重新执行健康检查和核心冒烟。

## 上线后验收

上线后至少覆盖：

- `https://woyai.cn/api/health` 返回 `status: ok`。
- 前端主站可加载首页资源。
- 登录链路可获得 JWT。
- 会员权限页和核心工具页可访问。
- 本轮涉及接口返回 HTTP 2xx，且业务字段完整。
- 生成类工具返回 `degraded=false` 或明确可接受的业务兜底状态。
- 抖音经营闭环需验证计划保存、任务状态更新、复盘保存、最近复盘读取和复盘洞察。

## 内测验证码处理

`INTERNAL_TEST_VERIFICATION_CODE` 只用于受控内测。正式对外发布前应清空该变量，并确认短信验证码或正式登录链路可用。
