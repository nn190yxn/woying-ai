# 经营闭环

## 概念

经营闭环是我赢AI当前产品组织方式，目标是让本地生活老板从问题判断走到每日执行，再通过数据复盘进入下一轮计划。

核心路径：

```text
经营体检 -> 作战计划 -> 执行工具 -> 数据复盘 -> 下一轮计划
```

## 体检

体检用于判断经营短板、置信度和下一步动作。当前覆盖：

- 抖音体检：`/douyin/diagnosis`。
- 小红书账号体检：`/xhs/account-diagnosis`。
- 私域体检：`/private/diagnosis`。

体检报告应提供：

- 诊断分型。
- 主短板。
- 置信度。
- 诊断依据。
- 风险边界。
- 推荐下一步动作。

## 作战计划

作战计划把体检结果转为可执行任务。抖音样板页是 `/douyin/quick-plan`。

15 天计划以表格呈现，每天包含目标、内容类型、拍摄方式、执行工具、投流计划、客户培育、复盘指标和任务状态。

## 执行工具

执行工具承接每日任务，减少用户从计划到行动之间的转换成本。抖音链路当前优先连接：

- 脚本生成。
- 标题优化。
- 封面助手。
- 转化链路。
- 本地推策略。
- 投流评估。
- 视频复盘。

## 数据复盘

数据复盘用于记录执行结果，当前抖音复盘页是 `/douyin/video-diagnoser`。

首期复盘字段包括：

- 执行天数。
- 内容产出。
- 播放。
- 完播。
- 评论。
- 私信。
- 咨询。
- 核销。
- 成交额。
- 投流消耗。

## 下一轮计划

复盘记录沉淀后，系统通过 `/api/douyin/review-records/insights` 统计有效内容类型和短板，生成下一轮计划建议。前端把有效内容类型、复盘建议和关键数据摘要传回 `/douyin/quick-plan`，后端 quick-plan prompt 再读取这些上下文生成新一轮计划。

## 设计原则

- 每个页面都应回答用户下一步做什么。
- 诊断结论要带依据和风险边界。
- 计划要能落到每天任务。
- 执行工具要从计划直接进入。
- 复盘要沉淀到下一轮计划。
- 会员升级提示应绑定更高级的经营结果。
