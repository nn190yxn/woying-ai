# 响应协议与错误口径

## 目标

本文档统一说明前后端接口响应、错误字段、鉴权状态和生成类工具结果协议。新增接口时应优先遵循当前代码已经使用的字段口径。

## 请求基础约定

| 项 | 约定 | 位置 |
| --- | --- | --- |
| API 前缀 | `/api` | `backend/src/index.js` |
| 前端 baseURL | `VITE_API_BASE_URL` 或 `/api` | `frontend/src/api/request.js` |
| 请求超时 | 30000 ms | `frontend/src/api/request.js` |
| 鉴权头 | `Authorization: Bearer <token>` | `frontend/src/api/request.js` |
| JSON body 限制 | 1 MB | `backend/src/index.js` |

前端响应拦截器直接返回 `response.data`，页面代码拿到的是后端响应体本身。

## 健康检查协议

接口：`GET /api/health` 和 `GET /health`。

响应：

```json
{
  "status": "ok",
  "timestamp": "2026-07-10T00:00:00.000Z"
}
```

用途：本地启动、线上发布后、PM2 重启后和回滚后验证服务可用性。

## 常规成功响应

当前项目存在两类成功响应。

### 直接资源响应

用于健康检查、列表、详情、用户资料、订单查询等接口。

示例：

```json
{
  "id": 11,
  "phone": "13800000000",
  "memberLevel": "annual"
}
```

### 状态包装响应

用于专项工具、保存计划、保存复盘和部分生成类接口。

示例：

```json
{
  "status": "success",
  "result": {},
  "upgradeHint": "升级后可解锁更完整能力"
}
```

新增专项接口建议使用状态包装响应，便于页面判断执行结果。

## 通用生成结果协议

通用工具结果由 `backend/src/services/resultSchema.js` 生成，核心字段如下：

| 字段 | 含义 |
| --- | --- |
| `status` | `ok` 或 `fallback` |
| `degraded` | 是否走降级或兜底 |
| `summary` | 结果摘要或核心结论 |
| `sections` | 分段展示内容 |
| `actions` | 行动建议 |
| `recommendedTools` | 推荐下一步工具 |
| `riskNotes` | 风险边界 |
| `scores` | 评分结果 |
| `dimensionRank` | 维度排序 |
| `benchmarks` | 行业基准 |
| `customizationCTA` | 会员升级或定制引导 |
| `meta.engineType` | 执行引擎类型 |
| `meta.toolCode` | 工具 code |
| `meta.fallbackType` | fallback 类型 |
| `result` | 领域内层结构，仅 `createDomainToolResult()` 包含 |

生成类工具验收应同时检查外层统一字段和页面实际消费的内层字段。

## 领域内层结构

专项工具可以在 `result` 中保留业务字段。例如：

- 抖音体检：`radarData`、`weakestDimension`、`benchmarks`、`recommendedActions`。
- 抖音计划：`phases`、`days`、每日任务字段。
- 抖音复盘：`analysis`、`effectiveContentTypes`、`nextActions`。
- 小红书工具：账号诊断、起号计划、脚本、封面和复盘字段。
- 私域工具：会员体系、社群 SOP、CAC vs LTV 和 90 天策略字段。

前端页面应优先读取明确的领域字段，同时兼容统一外层摘要和行动建议。

## 常规错误响应

后端常见错误字段为 `message`、`error`、`errors` 和 `details`。

前端会把错误统一规范化为：

```json
{
  "code": "HTTP_400",
  "message": "请求失败原因",
  "details": null
}
```

规范化来源顺序：

1. `data.message`
2. `data.error`
3. Axios error message
4. 默认文案 `请求失败`

## HTTP 状态码口径

| 状态码 | 使用场景 | 前端处理 |
| --- | --- | --- |
| 200 | 请求成功 | 渲染响应数据 |
| 400 | 参数错误、验证码错误、计划内容为空、任务状态无效 | 展示 normalized message |
| 401 | 未登录、token 缺失或 token 无效 | 清理 token 并跳转 `/login` |
| 403 | 会员等级不足、用户不存在、无访问权限 | 展示升级或权限提示 |
| 404 | 资源不存在，例如尚未保存计划 | 展示空状态或提示 |
| 500 | 服务端异常、数据库或 AI 失败 | 展示失败提示并查看日志 |

## 鉴权错误口径

通用鉴权中间件和专项路由存在不同实现，统一消费口径如下：

| 场景 | 常见响应 |
| --- | --- |
| 未带 token | `{ "error": "未授权", "requiredLevel": "free" }` 或 401 |
| token 无效 | `{ "error": "无效的 Token" }` |
| 用户不存在 | `{ "error": "用户不存在" }` |
| 会员等级不足 | `{ "error": "需要更高会员等级", "requiredLevel": "pro" }` |

前端页面应根据 HTTP 401 处理登录，根据 HTTP 403 处理升级引导。

## 校验错误口径

`express-validator` 错误通常返回：

```json
{
  "errors": []
}
```

业务校验错误通常返回：

```json
{
  "message": "计划内容不能为空"
}
```

新增接口建议优先返回 `message`，方便前端错误规范化。

## 降级和 fallback 口径

深测运行器会识别以下降级信号：

| 信号 | 含义 |
| --- | --- |
| `degraded: true` | 结果走降级路径 |
| `status: "fallback"` | 结果来自 fallback |
| `isFallback: true` | 专项工具显式标记 fallback |
| `isRuleFallback: true` | 小红书等专项工具规则兜底 |

生成类工具发布要求非预期降级为 0。fallback 可以作为异常兜底，验收时仍要记录原因。

## 新增接口响应建议

新增接口建议遵循：

- 成功响应包含业务主体数据。
- 写操作成功时返回 `status: "success"` 和关键资源摘要。
- 参数错误返回 400 和 `message`。
- 权限不足返回 401 或 403，并附带 `requiredLevel`。
- 服务端异常返回 500 和可展示 `message`。
- 生成类工具返回统一外层协议和页面消费字段。
- 用户数据读取和写入都带当前用户约束。

## 验收检查

响应协议相关改动至少检查：

- 前端是否仍能通过 `request.js` 拿到响应体。
- 401 是否清理 token 并跳转登录。
- 403 是否显示升级引导。
- 400 和 500 是否显示可理解错误文案。
- 生成类工具是否包含 `summary/actions/riskNotes/meta`。
- 页面实际读取的内层字段是否存在。
- deep:test 是否无 `INPUT_MISMATCH` 和非预期 `DEGRADED`。
