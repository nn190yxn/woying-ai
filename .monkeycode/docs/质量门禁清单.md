# 质量门禁清单

## 使用场景

本清单用于功能开发完成、线上部署前、线上部署后和交付内测前的固定检查。所有门禁项都应给出明确状态：`PASS`、`FAIL`、`BLOCKED` 或 `N/A`。

## 代码门禁

| 检查项 | 通过标准 | 证据 |
| --- | --- | --- |
| 变更范围 | 只改本轮任务相关文件 | `git status --short` |
| 后端语法 | 改动的后端 JS 文件全部 `node --check` 通过 | 命令输出无错误 |
| 前端构建 | `frontend` 下 `npm run build` 通过 | Vite build 完成 |
| 路由挂载 | 新后端路由已在 `backend/src/index.js` 挂载 | 代码检查 |
| 前端入口 | 新页面已在 `frontend/src/router/index.js` 和对应 Hub 注册 | 代码检查 |
| 请求封装 | 前端 API 优先复用 `@/api/request` | 代码检查 |
| mock 数据层 | 新持久化表同步支持 mock DB | `mockDb.js` 检查 |

## 数据门禁

| 检查项 | 通过标准 | 证据 |
| --- | --- | --- |
| 用户隔离 | 用户数据查询均带 `user_id` 或当前用户约束 | SQL 检查 |
| JSON 字段 | 写入前可序列化，读取后可解析 | 接口冒烟 |
| 表初始化 | 新表有初始化或明确迁移路径 | `db.js` 或部署记录 |
| 生产 DB | 线上使用真实 MySQL | 日志或健康检查证据 |
| mock 边界 | 生产环境查询失败会抛错 | `db.js` 行为确认 |

## 最低发布门槛

发布前最低通过项：

- 代码门禁全部 `PASS`。
- 鉴权与权限门禁全部 `PASS` 或有明确 `N/A`。
- 前端构建通过。
- 后端语法检查通过。
- 核心冒烟通过。
- 本轮新增接口冒烟通过。
- 线上备份已完成。
- 回滚路径已写明。
- 敏感信息检查无命中。

生成类工具发布还必须满足：专业度深测通过，且非预期 `DEGRADED` 为 0。
