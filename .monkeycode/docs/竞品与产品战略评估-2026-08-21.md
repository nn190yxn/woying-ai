# 我赢AI竞品与产品战略评估（2026-08-21）

> 作者：Monkeycode  
> 阶段假设：内部验证期  
> 第一核心客户：儿童素质类培训机构（从少儿体育培训开始）  
> 拟定商业模式：软件 + 陪跑服务

## 一、执行摘要

我赢AI存在真实价值，但当前价值主要体现为“陪跑交付基础设施”，还不是成熟的独立SaaS。

最核心的问题不是功能不足，而是：

> 有建议，但缺少真实经营数据；有计划，但不能自动执行；有复盘页面，但无法可靠归因到咨询、到店、核销和成交。

国内最强竞争者已经在向“经营型AI”演进：有赞把AI接入SaaS、PaaS、知识库和经营数据；美团依靠订单、评价、商圈与履约数据；微盟覆盖门店、会员、私域和营销执行；抖音来客直接掌握内容、投放、团购、交易和核销。

因此，我赢AI不应与平台争夺“全能经营操作系统”，第一阶段已经确定聚焦儿童素质类培训，并优先利用创始人在少儿体育培训领域的真实业务、结果和客户资源验证：

> 儿童素质培训15天抖音获客陪跑系统：诊断一个获客瓶颈、每天一个任务、每3天一次真人纠偏、完整记录咨询—邀约—到店体验—报名成交—续费转介绍结果。

## 二、竞品格局

真正的竞品不是功能长得一样的软件，而是争夺商家同一笔“增长预算”的产品与服务。

### 2.1 直接经营型竞品

| 产品 | 核心能力 | 强于我赢AI的地方 | 留给我赢AI的空位 |
| --- | --- | --- | --- |
| 有赞AI经营底座 / 有赞龙虾 | 连接SaaS、PaaS、知识库和经营数据，覆盖获客、转化、复购、经营任务 | 有真实会员、商品、订单、客户和执行通路 | 小商家可能仍需要更强的人陪、行业判断和跨平台策略 |
| 微盟WAI / 星元 | 店铺搭建、内容、营销、数据、私域、预约、会员和门店经营 | 业务系统完整，具备门店与会员基础设施 | 产品复杂、偏系统交付，我赢AI可在轻量陪跑上切入 |
| 美团智能掌柜 / 袋鼠管家 / CatPaw | 评价、订单、菜单、商圈、选址、营销诊断、异常巡检与Agent工作台 | 掌握本地生活最关键的真实数据，建议可直接嵌入平台工作流 | 主要围绕美团生态；跨平台经营和真人陪跑仍有空间 |

### 2.2 平台型替代品

| 产品 | 用户为什么会直接使用它 | 对我赢AI的威胁 |
| --- | --- | --- |
| 抖音来客 / 巨量本地推 | 门店、团购、短视频、直播、投放、数据、交易、核销一体化 | 用户可能不愿把抖音数据再手工录入第三方工具 |
| 蝉妈妈AI | 有抖音内容、电商、达人、竞品和投流数据，兼顾脚本与视频拆解 | 数据洞察比纯提示词生成更可信 |
| 企业微信SCRM | 客户沉淀、群运营、标签、触达、复购直接发生在客户关系链中 | 私域建议如果不能执行，就会被SCRM内置AI取代 |
| 通用大模型 | 成本低、入口熟悉、内容能力快速提升 | 脚本、标题、文案和普通诊断极易被替代 |

### 2.3 海外参考产品

| 产品 | 值得学习的产品逻辑 |
| --- | --- |
| HubSpot Breeze | AI必须建立在统一CRM数据上，并进入营销、销售、客服工作流 |
| Thryv | 本地商家关心的是被找到、获得线索、自动跟进和ROI，而不是工具数量 |
| Durable | 用“AI business partner”统一网站、CRM、营销和业务上下文 |
| GoDaddy Airo | 用户只表达目标，系统自动拆任务并完成建站、品牌和营销动作 |
| Wix AI | AI与网站、预约、电商、CRM、SEO和营销底座一起交付 |
| Jasper | 生成内容的差异化来自品牌知识、语气一致性、协作和治理，而不是单次文案 |

### 2.4 “抖音智能体”是否已经很多

结论：**数量很多，真正完整的经营型产品不多。**

市场可分为四层：

1. **低门槛智能体/技能**：扣子、Dify、各类Agent商店里有大量账号定位、选题、标题、脚本、爆款拆解和复盘技能。开发门槛低、同质化最严重，通常只是Prompt、知识库与搜索的组合。
2. **专业数据工具**：蝉妈妈、飞瓜、新抖、抖查查等掌握内容、达人、电商、直播或竞品数据，竞争力显著强于纯生成工具。
3. **官方经营工具**：抖音来客、巨量本地推及平台内置AI能力掌握门店、团购、投放、交易和核销，是最强的平台型替代品。
4. **代运营/陪跑服务**：大量官方服务商和本地运营公司提供诊断、脚本、拍摄、投流、复盘与陪跑。它们虽不一定是软件，却直接争夺商家的增长预算。

和我赢AI最接近的“诊断 + 计划 + 内容 + 复盘 + 真人陪跑”独立软件并没有普通脚本智能体那么泛滥，但其每个环节都面临成熟替代品。因此差异化不能建立在功能组合上，只能建立在特定行业结果、真人交付体系和经营结果数据上。

## 三、软件角度

### 最大缺点

**产品覆盖了经营闭环的名词，却没有掌握经营闭环的数据与执行权。**

代码事实：

- AI主要是知识库上下文加通用聊天模型：`backend/src/services/ai.js:4-51`、`backend/src/services/kbService.js:12-83`。
- 抖音指标依赖用户手工录入，并按固定阈值生成建议：`backend/src/routes/douyinAgents.js:1198-1215`。
- 15天计划主要由规则或模型生成：`backend/src/routes/douyinAgents.js:1375-1430`。
- 复盘保存的是用户提交的数据和建议，没有自动读取平台结果：`backend/src/routes/douyinAgents.js:1285-1315`。

这使产品目前更像“专业经营知识工具箱”，而不是能持续替老板工作的经营系统。

### 次要缺点

1. 功能过多，价值入口不清晰。
2. 115+工具制造选择成本，不能替老板减少决策。
3. 数据重复录入，难以形成长期使用习惯。
4. 报告和内容容易被通用大模型替代。
5. 支付、短信、安全和发布管理尚未达到成熟商业SaaS水平。

## 四、用户角度

### 最吸引我的地方

不是工具数量，而是：

> 把陪跑老师的经验变成今天可以照着执行的任务单。

尤其是“诊断 → 15天计划 → 选题脚本 → 执行 → 复盘”主线，对缺运营团队的老板有实际吸引力。它降低了“不知道今天做什么”的焦虑。

### 最不吸引我的地方

1. 首页和产品入口很多，不知道第一步应该做什么。
2. 需要自己填写很多平台已有的数据。
3. AI报告看起来完整，但无法证明能增加咨询、到店或成交。
4. 学习一个新系统的成本，可能高于直接问豆包、DeepSeek或陪跑老师。
5. 如果没有真人检查执行，15天计划容易变成又一份没有完成的计划表。

用户的真实判断不是“功能是否强”，而是：

- 它今天替我少做了什么？
- 它帮我多赚了多少钱？
- 出问题时有没有人负责？

## 五、架构师角度

### 最大缺陷

**系统以页面、路由和生成器为中心，而不是以统一经营数据模型和任务执行引擎为中心。**

证据：

- 后端存在大量平行功能路由：`backend/src/index.js:24-68`。
- 数据模型主要是用户、订单、工具使用、工具结果和诊断，缺少统一的门店、账号、内容、活动、线索、到店、核销、成交与归因实体：`backend/docs/schema.sql:4-99`。
- 抖音专项表与主Schema分裂：`backend/src/models/db.js:70-117`。
- AI层没有统一的任务编排、工具调用、人工审批、执行回执、重试和幂等机制：`backend/src/services/ai.js:9-59`。

### 应建立的业务内核

最小领域模型：

```text
Merchant / Store
  -> ChannelAccount
  -> Campaign
  -> ContentAsset
  -> DailyTask
  -> Spend
  -> Lead
  -> Appointment
  -> Visit
  -> Redemption
  -> Transaction
  -> Review / Intervention
```

架构优先级：

1. 独立租户与角色权限，先修复annual等同管理员。
2. 正式数据库迁移，不再依赖运行时建表和静默Mock。
3. 统一经营事件模型和归因口径。
4. 数据接入适配层：API、CSV、截图OCR、顾问代录。
5. 可恢复的工作流引擎：任务、审批、重试、回执、人工接管。
6. AI质量评测、成本追踪和业务结果评测分离。

## 六、创业导师角度

### 有没有价值

**有，但现在更适合作为服务交付产品，而不是独立售卖的全能SaaS。**

### 最大价值

1. 把创始人的陪跑方法论标准化。
2. 降低顾问做诊断、出计划、写脚本和复盘的时间。
3. 让不同陪跑老师按照统一流程交付。
4. 最终沉淀“商家问题—经营动作—人工干预—结果”的独有数据。

真正可能形成壁垒的不是Prompt和知识库，而是：

> 哪类门店在什么情况下，执行什么动作，由什么顾问怎样纠偏，最终带来了多少咨询、到店、核销和成交。

### 最差的地方

**把产品规模误当成产品成熟度。**

内部验证阶段已经建设大量行业、渠道、工具和会员能力，但尚未证明一个狭窄场景可以稳定产生付费和经营结果。

### 最值得改进的地方

- 从“给建议”转向“盯执行”。
- 从“生成内容”转向“记录结果”。
- 从“卖会员”转向“卖一个有期限、有指标的陪跑周期”。
- 从“服务所有中小企业”转向“服务一类有明确获客问题的门店”。
- 从“115个工具”转向“用户每天只有一个明确下一步”。

## 七、建议砍掉与聚焦

### 暂停新增和弱化销售

- 小红书完整智能体矩阵。
- 泛私域工具矩阵。
- 更多行业版本。
- 零散海报、计算器和低频生成器。
- 在没有付费验证前继续扩展复杂会员体系。

不是立即删除代码，而是停止投入、隐藏次要入口，避免继续扩大维护面。

### 唯一主产品建议

**儿童素质培训15天抖音获客陪跑系统**

完整流程：

1. 选择一家儿童素质培训机构和一个主推课程/体验产品。
2. 建立当前内容、咨询、有效线索、邀约、到店体验、报名、续费与转介绍基线。
3. 诊断一个主要瓶颈。
4. 每天只分配一个关键任务。
5. AI生成选题、脚本和执行材料。
6. 顾问在发布前审核关键内容。
7. 每天回收最少量结果数据。
8. 每3天一次人工纠偏。
9. 第15天输出效果对比和下一周期决策。

### 内部验证只看四个指标

1. 15天任务完成率。
2. 首次有效内容产出时间。
3. 有效咨询、邀约、到店体验、报名数量及获客成本变化。
4. 首周期结束后的续费或转介绍率。

不要再用工具数、生成次数和报告数证明价值。

## 八、最终判断

### 当前评分

| 维度 | 判断 |
| --- | --- |
| 产品展示完整度 | 较高 |
| 立即可理解性 | 偏低 |
| 独立SaaS成熟度 | 较低 |
| 陪跑交付价值 | 较高 |
| 当前技术壁垒 | 较低 |
| 数据壁垒潜力 | 较高，但尚未形成 |

### 一句结论

> 现在的我赢AI不是商家的AI经营系统，而是一套知识很多、入口很多、却既不掌握经营数据也不替老板执行的陪跑工具箱；如果不砍到一个能证明成交结果的场景，它会同时输给平台型竞品和通用大模型。
