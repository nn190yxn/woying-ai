# 排错手册

## 排查顺序

遇到线上或本地异常时，建议按以下顺序排查：

1. 健康检查和进程状态。
2. 前端资源和 API 代理。
3. 鉴权、会员等级和 token。
4. 数据库、Redis 和知识库路径。
5. AI 网关、结构化输出和 fallback。
6. 业务接口输出结构和专业度。

## 服务无法访问

先检查健康接口：

```bash
curl -fsS https://woyai.cn/api/health
```

期望返回：

```json
{
  "status": "ok"
}
```

线上后端由 PM2 管理，服务名为 `woying-backend`。服务异常时检查 PM2 状态和日志，再决定是否回滚。

```bash
pm2 status woying-backend
pm2 logs woying-backend
```

后端也提供 `GET /health`，适合在服务器内网或本地端口上直接验证 Express 服务。

## 前端页面空白或接口 404

前端本地开发默认端口为 `5173`，后端默认端口为 `3001`。Vite 代理默认读取 `VITE_API_TARGET`，否则指向 `http://localhost:3000`。

本地联调推荐命令：

```bash
cd frontend
VITE_API_TARGET=http://localhost:3001 npm run dev
```

排查点：

- 浏览器 Network 中确认静态 chunk 返回 HTTP 200。
- `/api/health` 是否代理到实际后端端口。
- `frontend/src/api/request.js` 是否自动注入 `Authorization`。
- 页面路由是否已在 `frontend/src/router/index.js` 注册。

## 登录失败或 401

后端通用鉴权在 `backend/src/middleware/auth.js`。

生产环境要求配置 `JWT_SECRET`。缺失时，受保护接口会返回服务端认证配置缺失。非生产环境默认启用 guest mode，除非设置 `GUEST_MODE=false`。

排查点：

- 登录接口是否返回 `token`。
- 前端是否把 token 写入 `localStorage.token`。
- 请求头是否包含 `Authorization: Bearer <token>`。
- JWT 是否由当前运行环境的 `JWT_SECRET` 签发。
- 专项路由是否基于 `userId` 查询到了用户会员等级。

## 验证码异常

验证码由 `backend/src/routes/auth.js` 写入 Redis key：`code:<phone>`，有效期 300 秒。

Redis 默认使用 `backend/src/config/mockRedis.js` 的内存实现。设置 `USE_REAL_REDIS=true` 后，会使用 `REDIS_URL` 或 `REDIS_HOST` 连接真实 Redis。

排查点：

- `USE_REAL_REDIS` 是否符合当前环境预期。
- Redis 连接日志是否出现 `Connected` 和 `Ready`。
- 测试环境是否配置了 `INTERNAL_TEST_VERIFICATION_CODE`。
- 正式公开发布前是否已清空内测验证码配置。

## 数据库异常

数据库入口是 `backend/src/models/db.js`。

非生产环境中，MySQL 连接失败会降级到内存 mock DB。生产环境查询失败会抛错并写入错误日志。

排查点：

- `DB_HOST` 或 `MYSQL_HOST` 是否指向正确 MySQL。
- `DB_NAME` 或 `MYSQL_DATABASE` 是否存在。
- 线上错误日志是否包含 `Query failed in production`。
- 新增业务表是否已由 `initDB()` 或接口懒初始化创建。
- 计划、复盘等用户数据是否被写入真实 MySQL。

与抖音闭环相关的表：

- `douyin_quick_plans`
- `douyin_review_records`

## AI 生成失败

AI 调用集中在 `backend/src/services/ai.js`，使用 Chat Completions 协议，请求路径为 `{BASE_URL}/chat/completions`。

项目侧推荐配置：

- `USER_LLM_API_KEY`
- `USER_LLM_BASE_URL`
- `USER_LLM_MODEL`
- `AI_REQUEST_TIMEOUT`

常见现象和排查点：

- `AI API key not configured`：项目侧 AI Key 未配置。
- `AI 请求超时`：上游响应超过 `AI_REQUEST_TIMEOUT`。
- `AI API error: 401`：项目侧 Key 或鉴权方式异常。
- `AI API error: 404`：base URL 与 `/chat/completions` 拼接后路径异常。
- 返回文本无法解析 JSON：检查对应路由是否启用 `responseFormat: { type: 'json_object' }`，并查看 fallback 是否生效。

## 知识库未命中

知识库服务位于 `backend/src/services/kbService.js`。生产环境默认知识库路径为 `/home/ubuntu/woying-ai/knowledge-base`，开发环境默认使用仓库内 `knowledge-base/`。

排查点：

- `KB_ROOT_PATH` 是否指向存在的目录。
- 工具 code 是否已映射到对应知识库文件。
- `KB_MAX_CONTEXT_CHARS` 和 `KB_MAX_FILE_CHARS` 是否过小。
- 生成结果是否走了规则 fallback。

## 工具返回 degraded

深测运行器会识别 `degraded=true`、`status=fallback` 或 `isFallback=true`。生成类工具出现 degraded 时，按以下顺序排查：

1. 输入 payload 是否满足 `CALCULATORS.inputs` 或路由校验要求。
2. AI 网关是否返回错误或超时。
3. 知识库映射是否命中。
4. fallback 输出结构是否与前端页面协议一致。
5. 前端是否读取了正确的 `result` 内层字段。

## 抖音计划保存失败

涉及文件：

- `backend/src/routes/douyinAgents.js`
- `backend/src/models/db.js`
- `backend/src/models/mockDb.js`
- `frontend/src/views/douyin/QuickPlanAgent.vue`

排查点：

- 当前用户是否达到 `starter`。
- `douyin_quick_plans` 是否存在。
- `plan` 是否为可 JSON 序列化对象。
- 读取保存计划时 `user_id` 是否与当前 JWT 用户一致。
- 每日状态更新是否命中正确 `day`。

## 抖音复盘洞察为空

复盘洞察基于当前用户最近 20 条 `douyin_review_records` 聚合。

排查点：

- 当前用户是否达到 `pro`。
- 是否已保存至少一条复盘记录。
- `effective_content_types` 是否有可解析内容。
- `input_data` 中是否包含播放、完播、咨询、核销、ROI 等指标。
- 从复盘页跳回计划页时路由 query 是否带上有效内容类型和复盘建议。

## 日志位置

日志目录由 `LOG_DIR` 控制，默认是当前工作目录下的 `logs`。

日志文件类型：

- `request.log`：请求、普通应用日志和 Redis / DB 状态。
- `error.log`：错误日志。
- `audit.log`：工具、登录、支付、会员、后台操作审计。

日志会在午夜按日期轮转。排查工具失败时，优先搜索 `error.log` 和 `audit.log` 中的 `toolCode`、`userId` 和错误消息。

## 发布后回归

发布后建议依次执行：

```bash
# 健康检查
curl -fsS https://woyai.cn/api/health

# 后端核心冒烟
cd backend
BASE_URL=https://woyai.cn npm run smoke:core
```

涉及生成质量的发布，还应执行深测或人工专业度验收，重点确认字段结构、行业依据、行动建议和风险边界。
