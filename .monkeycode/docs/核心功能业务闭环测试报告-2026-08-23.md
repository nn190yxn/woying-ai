# 核心功能业务闭环测试报告（2026-08-23）

> 作者：Monkeycode

## 1. 测试目标

验证融合知识库是否真正进入儿童培训机构业务链，是否能从真实经营输入产生诊断、行动计划、阶段复盘和顾问升级，并评估当前产品是否方便机构老板使用。

## 2. 测试样本

匿名少儿篮球机构，贵阳，少儿篮球体验课。月曝光 12,000、有效咨询 28、预约 12、到店 3、完成体验 3、正价报名 0、投放 1,800 元。业务问题为“内容有播放但咨询有限，体验课到店后没有正价报名”。同时注入虚构儿童姓名和手机号验证脱敏。

## 3. 自动化闭环

新增 `backend/scripts/core-business-loop.test.js`，覆盖：

1. 创建机构与长期获客项目；
2. 按获客诊断、体验产品、投流实验三个维度检索知识；
3. 通过统一 Runner 注入知识上下文并生成结构化诊断；
4. 保存真实聚合经营快照并计算转化指标；
5. 识别周复盘唯一主问题；
6. 保存 7 天行动计划；
7. 对零成交高风险触发人工顾问升级；
8. 验证姓名、手机号脱敏；
9. 验证未配置模型时明确进入 `needs_review`，不伪造 AI 成功。

执行结果：四类匿名业务样本与核心闭环专项测试 4/4 通过；后端全量回归 117/117 通过；前端 Vite 生产构建通过。测试环境 MySQL 不可用，使用 Mock DB。

## 4. 实际知识命中

- `funnel-traffic`：曝光有但有效咨询少时检查内容匹配、信任、产品和承接；
- `douyin-dynamic`：抖音动态规则必须复核；
- `cross-industry-limit`：跨行业材料不得直接生成儿童培训强制动作；
- `trial-offer`：体验课必须明确适龄、目标、过程、反馈和正价课衔接；
- `traffic-experiment`：先检查基建、自然信号、承接和利润，再做小额试验；
- `traffic-prohibition`：没有承接、利润、预算和停止条件时禁止扩大投流。

结论：知识库不是仅存储在文件中，结构化知识能够被检索并进入 Runner 上下文。

## 5. 实际业务结果

诊断结论：主要瓶颈在到店后的体验承接与成交，而非继续扩大投流。

计算结果：

- 有效咨询成本：约 64.29 元；
- 预约到店率：25%；
- 体验课正价转化率：0%；
- 周复盘主问题：到店未形成正价成交。

生成动作：

1. 负责人在 7 天内重做体验课承接卡，验证体验到正价转化；
2. 营销负责人用 7 天只测试一个家长问题内容方向，验证有效咨询；
3. 连续两轮无改善、预算超限或出现隐私风险时停止；
4. 零成交触发高优先级人工顾问介入。

该结果与输入数据一致，避免了在成交承接未验证时继续扩大投流，具备业务合理性和执行方向。

## 6. 测试发现并已修复

1. `childName` 未被敏感字段脱敏规则覆盖，可能进入模型上下文；已在 `backend/src/services/aiRunner.js` 修复。
2. Runner 审计中的知识命中数量读取了不存在的 `meta.count`，实际结构使用 `meta.snippetCount`，导致审计显示 0；已修复并保留兼容读取。

## 7. 当前产品闭环状态与限制

### 已完成：老板端最小可用闭环

`frontend/src/views/growth/AcquisitionEngine.vue` 已提供：

- 本周问题选择器、课程/年龄段/城市和聚合漏斗指标表单；
- 诊断结果中的主问题、证据、知识依据、核验状态、行动、验证指标和停止条件；
- 一键保存 7 天行动计划；行动计划继承诊断最多两个优先动作、验证指标和停止条件；
- 阶段快照录入、周复盘和四态建议展示；
- 保留项目历史、机构请求头、错误重试与响应式布局。

### 限制一：默认环境不能产生真实 AI 诊断

未配置 LLM API Key 时，`createDiagnosis` 保留确定性规则诊断但状态为 `needs_review`，不会伪造 AI 成功。这意味着真实模型质量尚未验证，人工核验仍是必要步骤。

### 限制二：本轮仅验证匿名聚合数据

未接入 OCR、语音、CRM、支付或真实媒体供应商；没有使用真实追光小牛数据。项目无现成前端组件测试框架，因此前端以 Vite 构建和后端协议/全量回归作为验证。

## 8. 验收判断

| 维度 | 判断 | 说明 |
|---|---|---|
| 知识库能否使用 | 通过 | 真实命中 6 条跨诊断、体验课和投流知识 |
| 能否产生合理结果 | 条件通过 | 本地结构化 Runner 能形成合理结论；真实模型质量尚未验证 |
| 数据与隐私安全 | 通过 | 测试发现并修复 `childName` 脱敏遗漏 |
| 行动与复盘闭环 | 后端通过 | 诊断、计划、指标、复盘、顾问升级均可运行 |
| 老板使用便利性 | 条件通过 | 匿名聚合数据的表单、诊断、行动、快照和复盘链已打通；真实业务资料仍需后续验证 |
| 当前能否直接交付客户 | 不通过 | LLM 未配置时仍为 `needs_review`，且本轮未接真实数据/供应商 |

## 9. 总结

融合知识库已经具备可检索、可注入、可约束诊断和行动的技术能力；四类匿名样本能够得到相互区分且符合漏斗数据的业务判断。老板端的结构化 7 天闭环已可操作，但真实模型、真实机构数据和外部供应商仍未接入。下一阶段应优先用授权的真实少儿体育机构数据做小范围验证，再决定是否接入 OCR、CRM 或真实 LLM。
