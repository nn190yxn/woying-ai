# 新成员接手清单

## 目标

本清单用于新开发者、测试人员或运维人员接手我赢AI项目时快速建立上下文。按顺序完成后，应能理解系统边界、核心链路、运行方式、质量门禁和发布风险。

## 第 1 步：确认工作区

| 检查项 | 期望结果 |
| --- | --- |
| 仓库根目录 | `woying-ai/` |
| Wiki 目录 | `.monkeycode/docs/` |
| 规格目录 | `.monkeycode/specs/` |
| 前端目录 | `frontend/` |
| 后端目录 | `backend/` |
| 小程序目录 | `miniapp/` |
| 知识库目录 | `knowledge-base/` |

推荐先读：

- `.monkeycode/docs/INDEX.md`
- `.monkeycode/docs/术语表.md`
- `.monkeycode/docs/代码目录导览.md`
- `.monkeycode/docs/核心数据流.md`

## 第 2 步：理解产品主线

核心业务链路：

```text
经营体检 -> 作战计划 -> 执行工具 -> 数据复盘 -> 下一轮计划 -> 会员升级
```

需要重点理解：

- 抖音链路是当前样板闭环。
- 小红书和私域链路沿用专项 Hub 加专项工具的组织方式。
- 通用工具走 `/api/generate/:toolCode`。
- 会员等级同时影响前端入口和后端接口。

推荐阅读：

- `.monkeycode/docs/端到端业务流程.md`
- `.monkeycode/docs/专有概念/BusinessOpsLoop.md`
- `.monkeycode/docs/专有概念/MembershipAndAccess.md`
- `.monkeycode/docs/专有概念/ReviewInsights.md`

## 第 3 步：理解运行形态

本地开发涉及两个主要服务：

| 服务 | 默认目录 | 常用命令 | 说明 |
| --- | --- | --- | --- |
| 前端 | `frontend/` | `npm run dev`、`npm run build` | Vue 3 + Vite |
| 后端 | `backend/` | `npm run dev`、`npm start` | Express API |

线上关键点：

- 主站：`https://woyai.cn/`
- 健康检查：`https://woyai.cn/api/health`
- PM2 服务名：`woying-backend`
- 线上路径：`/home/ubuntu/woying-ai`

推荐阅读：

- `.monkeycode/docs/部署运行手册.md`
- `.monkeycode/docs/环境配置清单.md`
- `.monkeycode/docs/安全与配置边界.md`

## 第 4 步：理解代码边界

常见任务入口：

| 任务 | 优先看 |
| --- | --- |
| 改前端页面 | `frontend/src/views/`、`frontend/src/router/index.js` |
| 改工具入口 | `frontend/src/constants/toolCatalog.js`、对应 Hub 页面 |
| 改后端接口 | `backend/src/routes/`、`backend/src/index.js` |
| 改会员权限 | `frontend/src/constants/membership.js`、`backend/src/config/toolAccess.js`、专项 `requireLevel()` |
| 改数据库 | `backend/src/models/db.js`、`backend/src/models/mockDb.js` |
| 改 AI 输出 | `backend/src/services/ai.js`、`backend/src/services/kbService.js`、对应 route fallback |
| 改知识库 | `knowledge-base/`、`backend/src/services/kbService.js` |
| 改支付 | `backend/src/config/plans.js`、`backend/src/routes/payment.js` |

推荐阅读：

- `.monkeycode/docs/ARCHITECTURE.md`
- `.monkeycode/docs/INTERFACES.md`
- `.monkeycode/docs/前后端路由映射.md`
- `.monkeycode/docs/变更影响面指南.md`

## 第 5 步：理解核心数据

优先掌握这些表和用途：

| 表 | 用途 |
| --- | --- |
| `users` | 用户、会员等级、会员有效期 |
| `orders` | 会员订单和支付状态 |
| `tool_usage` | 工具调用和配额统计 |
| `tool_results` | 通用工具历史结果 |
| `diagnosis_reports` | 体检报告 |
| `douyin_quick_plans` | 当前用户最近一份 15 天计划 |
| `douyin_review_records` | 当前用户多条复盘记录 |
| `analytics_events` | 行为事件 |
| `user_feedbacks` | 用户反馈和后台处理 |

推荐阅读：

- `.monkeycode/docs/数据模型.md`
- `.monkeycode/docs/核心数据流.md`

## 第 6 步：执行基础验证

接手后先确认基础命令可运行：

```bash
# 前端构建
cd frontend
npm run build

# 后端抖音专项语法检查
cd ../backend
node --check src/routes/douyinAgents.js

# 抖音诊断专项测试
npm run test:douyin-diagnosis
```

如需完整验证，参考：

- `.monkeycode/docs/测试验收手册.md`
- `.monkeycode/docs/质量门禁清单.md`
- `.monkeycode/docs/发布验收记录模板.md`

## 第 7 步：处理常见问题

优先按问题类型阅读：

| 问题 | 文档 |
| --- | --- |
| 本地服务无法启动 | `.monkeycode/docs/排错手册.md` |
| 接口 401 或 403 | `.monkeycode/docs/安全与配置边界.md`、`.monkeycode/docs/排错手册.md` |
| AI 工具输出异常 | `.monkeycode/docs/测试验收手册.md`、`.monkeycode/docs/风险登记与后续治理.md` |
| 会员入口和接口不一致 | `.monkeycode/docs/专有概念/MembershipAndAccess.md` |
| 新增功能不知道影响范围 | `.monkeycode/docs/变更影响面指南.md` |
| 线上部署需要回滚 | `.monkeycode/docs/部署运行手册.md` |

## 第 8 步：确认当前风险

接手者应重点关注：

- 生成类接口耗时。
- AI 输出结构波动。
- Token Monitor 生产访问控制。
- 内容安全接口正式化。
- 内测验证码公开发布前处理。
- 前后端权限矩阵一致性。
- mock DB 与真实 MySQL 差异。
- `.monkeycode/docs/` 是否已纳入版本控制。

风险详情见 `.monkeycode/docs/风险登记与后续治理.md`。

## 第 9 步：变更前检查

开始任何开发任务前，先回答这些问题：

| 问题 | 判断依据 |
| --- | --- |
| 这次改动属于哪个模块 | `代码目录导览.md` |
| 会影响哪些接口和页面 | `前后端路由映射.md` |
| 是否影响会员权限 | `MembershipAndAccess.md` |
| 是否新增或修改数据表 | `数据模型.md` |
| 是否影响 AI 输出结构 | `测试验收手册.md` |
| 是否需要更新 Wiki | `Wiki 文档维护指南.md` |

## 第 10 步：交付前检查

交付前至少确认：

- 代码语法或构建命令通过。
- 新增接口有冒烟证据。
- 会员权限与前端入口一致。
- AI 结果满足结构和专业度要求。
- 相关 Wiki 已同步。
- 敏感信息检查无真实值。
- 发布或回滚路径已写明。

对应模板：

- `.monkeycode/docs/质量门禁清单.md`
- `.monkeycode/docs/发布验收记录模板.md`
