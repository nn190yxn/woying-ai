# 后端路由维护手册

## 目标

本文档说明 Express 后端路由的组织方式、新增接口流程、鉴权权限、响应协议、日志和验收要求。新增或修改后端接口时，应先检查本页。

## 应用入口

后端入口：`backend/src/index.js`。

启动流程：

```text
load dotenv
create express app
register cors and body parser
register requestLogger
register perfMonitor
mount routes
mount /health and /api/health
register errorTracker
listen on 0.0.0.0
```

请求体限制：JSON body 1 MB。

## 新增路由流程

1. 在 `backend/src/routes/` 新增或修改路由文件。
2. 选择鉴权方式：通用 `authMiddleware` 或专项 `checkAccess`。
3. 明确最低会员等级。
4. 如涉及持久化，同步 `db.js` 初始化或迁移路径。
5. 如本地需要运行，同步 `mockDb.js` 行为。
6. 在 `backend/src/index.js` 挂载路由前缀。
7. 更新 `INTERFACES.md` 和 `前后端路由映射.md`。
8. 增加冒烟或深测用例。

## 鉴权选择

| 场景 | 推荐方式 |
| --- | --- |
| 普通登录用户接口 | `authMiddleware` |
| 可选登录增强体验 | `optionalAuth` |
| 抖音、小红书、私域专项接口 | 专项 `checkAccess` 和 `requireLevel()` |
| 后台接口 | 管理员或高阶会员权限判断 |
| 支付回调 | 签名校验和状态校验 |

新增受保护接口时，用户 ID 应来自鉴权结果，不应信任前端传入的 `userId`。

## 会员权限

通用工具权限：`backend/src/config/toolAccess.js`。

专项工具权限：

- 抖音：`routes/douyinAgents.js`
- 小红书：`routes/xhsAgents.js`
- 私域：`routes/privateAgents.js`

权限不足建议返回 403，并附带可展示错误和 `requiredLevel`。

## 响应协议

常规错误字段：

- `message`
- `error`
- `errors`
- `details`

新增业务校验错误建议返回：

```json
{
  "message": "参数说明"
}
```

生成类工具应遵循统一结果协议，详见 `.monkeycode/docs/响应协议与错误口径.md`。

## 数据访问

数据层入口：`backend/src/models/db.js`。

规则：

- 生产环境查询失败抛错。
- 非生产环境可落到 mock DB。
- 用户数据查询必须带用户约束。
- JSON 字段写入前确保可序列化。
- 新表需要初始化、迁移或清晰的线上创建路径。

涉及用户数据时同步 `.monkeycode/docs/数据治理与隐私边界.md`。

## 日志和审计

应用日志：`backend/src/middleware/logger.js`。

新增接口建议：

- 请求日志由 `requestLogger` 自动记录。
- 慢请求由 `perfMonitor` 自动记录。
- 工具执行使用 `logger.toolStart()`、`toolSuccess()`、`toolFailure()`。
- 登录、支付、会员和后台动作使用对应 audit logger。
- 错误日志记录摘要和定位字段。

日志避免写入完整 token、真实密钥、支付签名和用户完整敏感输入。

## 通用工具路由维护

通用生成入口：`routes/generate.js` 的 `/api/generate/:toolCode`。

新增通用工具时检查：

- 工具定义。
- 工具权限。
- 输入校验。
- 执行引擎。
- 知识库映射。
- 结果协议。
- 使用计数和历史保存。
- 前端工具入口。
- deep:test payload。

## 专项路由维护

专项路由通常包含业务 prompt、结构化解析、fallback 和领域接口。

修改专项路由时检查：

- `checkAccess` 是否设置用户 ID 和会员等级。
- `requireLevel()` 是否匹配前端入口。
- AI 输出是否需要 `responseFormat`。
- fallback 是否可被前端渲染。
- 数据表读写是否按用户隔离。
- 新接口是否写入 `INTERFACES.md`。

## 健康检查

后端提供两个健康接口：

- `GET /health`
- `GET /api/health`

响应：

```json
{
  "status": "ok",
  "timestamp": "2026-07-10T00:00:00.000Z"
}
```

部署后优先检查 `/api/health`。

## 语法和冒烟

修改路由后至少执行：

```bash
# 检查入口和改动路由语法
cd backend
node --check src/index.js
node --check src/routes/<route-file>.js
```

按影响范围执行：

```bash
# 核心冒烟
npm run smoke:core

# 全量深测
npm run deep:test

# 抖音专项测试
npm run test:douyin-diagnosis
```

## 常见遗漏

| 遗漏 | 后果 | 检查方式 |
| --- | --- | --- |
| 未在 `index.js` 挂载 | 接口 404 | 查看路由挂载表 |
| 未加鉴权 | 用户数据暴露 | 检查中间件和专项 `checkAccess` |
| 未带用户约束 | 跨用户读取 | SQL 检查 |
| 未同步 mock DB | 本地测试失败 | 运行本地接口 |
| 未更新前端调用 | 页面仍请求旧接口 | 浏览器 Network |
| 错误字段不可展示 | 前端提示为空 | 检查 `message` 或 `error` |
| fallback 结构不兼容 | 页面渲染失败 | deep:test 和页面检查 |
