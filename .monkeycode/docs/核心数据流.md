# 核心数据流

## 登录状态流

```text
Login/Register page
  -> /api/auth/login or /api/auth/register
  -> backend signs JWT
  -> frontend store writes localStorage.token
  -> request interceptor injects Authorization
  -> protected API reads req.user
```

前端 `stores/user.js` 负责：

- 保存 `token`。
- 保存 `userInfo`。
- 同步 `localStorage.token`。
- 同步 `localStorage.memberLevel`。
- 计算 `isLoggedIn`、`memberLevel`、`isAdmin`、`memberLabel`。

后端 `middleware/auth.js` 负责：

- 读取 `Authorization: Bearer <token>`。
- 使用 `JWT_SECRET` 校验 JWT。
- 把 decoded payload 写入 `req.user`。
- 非生产 guest mode 下补充年费等级访客用户。

前端路由守卫用 `localStorage.token` 判断 `requiresAuth`，用 `localStorage.memberLevel` 判断 `requiresAdmin`。

## 会员等级流

```text
orders paid
  -> users.member_level and member_expire_at updated
  -> /api/auth/login returns user.memberLevel
  -> localStorage.memberLevel
  -> frontend entry gating
  -> backend requireLevel checks users.member_level
```

会员等级来源以数据库 `users.member_level` 为准。前端本地会员等级用于入口展示和路由体验，后端接口权限仍需要查询用户等级。

通用工具权限：

- 前端工具目录来自 `frontend/src/constants/toolCatalog.js`。
- 后端通用工具权限来自 `backend/src/config/toolAccess.js`。

专项工具权限：

- 抖音：`backend/src/routes/douyinAgents.js`。
- 小红书：`backend/src/routes/xhsAgents.js`。
- 私域：`backend/src/routes/privateAgents.js`。

## 通用工具生成流

```text
Tool page
  -> generateTool() or generateWithAI()
  -> POST /api/generate/:toolCode
  -> authMiddleware
  -> member and quota checks
  -> engine execution
  -> tool_usage and optional tool_results
  -> frontend result render
```

前端入口：

- `frontend/src/api/index.js` 的 `generateTool()`。
- `frontend/src/api/tool.js` 的 `generateWithAI()`。

后端入口：

- `backend/src/routes/generate.js`。
- `backend/src/services/engineRegistry.js`。
- `backend/src/services/failover.js`。
- `backend/src/services/resultSchema.js`。

数据落点：

- `tool_usage`：工具使用计数和后台统计。
- `tool_results`：工具输入输出历史。
- `analytics_events`：行为和转化统计。

## 配额流

```text
Tool page
  -> quota store fetches /api/tools/quotas or /api/tools/:code/quota
  -> backend counts tool_usage
  -> frontend displays remain and total
  -> successful run consumes locally
```

前端 `stores/quota.js` 管理：

- `globalQuota`
- `allQuotas`
- `toolQuotas`
- `currentToolCode`
- `canUse()`
- `consume()`

本地扣减用于即时反馈，最终配额仍以后端 `tool_usage` 查询为准。

## 抖音计划数据流

```text
DiagnosisAgent
  -> /api/douyin/diagnosis
  -> route query carries diagnosisContext
  -> QuickPlanAgent
  -> /api/douyin/quick-plan
  -> /api/douyin/quick-plan/saved
  -> douyin_quick_plans
```

计划保存结构：

- `user_id`：当前登录用户。
- `industry`：行业。
- `goal`：目标。
- `frequency`：发布频次。
- `ad_support`：投流支持。
- `diagnosis_context`：体检上下文。
- `plan`：15 天计划 JSON。

同一用户只有一份最近计划。任务状态更新通过 `PATCH /api/douyin/quick-plan/saved/status` 修改 `plan` 内指定 day 的状态。

## 抖音复盘数据流

```text
QuickPlanAgent day task
  -> VideoDiagnoserAgent
  -> /api/douyin/data-diagnoser
  -> /api/douyin/review-records
  -> douyin_review_records
  -> /api/douyin/review-records/insights
  -> next QuickPlanAgent context
```

复盘记录包含：

- `source_context`：来源计划和当天任务上下文。
- `input_data`：播放、点赞、完播、咨询、核销、ROI 等输入。
- `result_data`：诊断结果。
- `effective_content_types`：有效内容类型。
- `next_actions`：下一步行动。

洞察接口读取最近 20 条复盘，聚合有效内容类型和关键指标，并输出下一轮计划建议。

## 诊断报告数据流

```text
Diagnosis page
  -> /api/diagnosis/v3/* question endpoints
  -> /api/diagnosis/v3/generate
  -> diagnosis engine and AI diagnosis
  -> diagnosis_reports
  -> report or history page
```

通用诊断依赖：

- `backend/src/services/diagnosisEngineV3.js`
- `backend/src/services/diagnosisEngine.js`
- `backend/src/services/aiDiagnosis.js`
- `backend/src/routes/diagnosis.js`

历史报告按用户隔离读取。

## 支付和推荐数据流

```text
Membership page
  -> /api/payment/create-order
  -> orders pending
  -> /api/payment/callback
  -> orders paid and users membership updated
  -> referral commission calculation
```

支付主链路：

- 套餐价格来自 `backend/src/config/plans.js`。
- 回调签名使用 `PAYMENT_CALLBACK_SECRET`。
- 支付成功使用事务和订单行锁。
- 会员有效期按套餐周期累加。

推荐链路：

- 注册时可带 `referralCode`。
- 用户表保存 `referred_by`。
- 支付成功后计算推荐佣金。
- 推荐失败只写日志，不影响支付主流程。

## 用户反馈数据流

```text
Membership feedback form
  -> POST /api/user-feedback
  -> user_feedbacks
  -> GET /api/user-feedback/my
  -> Admin feedback management
```

后台可以读取和更新反馈状态、后台备注。反馈数据和导出能力属于运营敏感面。

## 表格保存数据流

```text
Spreadsheet-capable tool
  -> POST /api/sheets/save
  -> user_sheets upsert by user_id + sheet_code
  -> GET /api/sheets/list or /api/sheets/load/:id
```

`user_sheets` 通过唯一索引保证同一用户同一表格代码只保存一份最新数据。

## AI 和知识库数据流

```text
tool input
  -> route prompt builder
  -> kbService retrieves markdown context
  -> ai.js calls chat completions
  -> JSON parse or text parse
  -> fallback if failed
  -> resultSchema wraps output
```

关键边界：

- AI 请求路径为 `{BASE_URL}/chat/completions`。
- 知识库根目录可通过 `KB_ROOT_PATH` 覆盖。
- 结构化输出路由优先使用 `responseFormat`。
- fallback 必须返回前端可渲染结构。

专业度验收需要同时检查字段结构和内容质量。

## 日志和监控数据流

```text
request
  -> requestLogger
  -> route handler
  -> logger writes request/error/audit logs
  -> tokenMonitor and qualityFeedback collect model usage
```

日志类型：

- `request.log`：请求和普通应用日志。
- `error.log`：错误日志。
- `audit.log`：工具、认证、支付、会员和后台操作审计。

token monitor 接口挂载在 `/api/token-monitor`，生产访问控制见安全与配置边界文档。

## 前端本地事件流

`frontend/src/api/index.js` 有本地事件缓存逻辑：

```text
trackEvent()
  -> localStorage._track_events
  -> flushEvents()
  -> POST /api/analytics/batch
```

事件最多保留最近 100 条，并在页面卸载或 30 秒定时触发 flush。新增服务端 analytics 接口时需要确认 `/api/analytics/batch` 的后端支持情况。
