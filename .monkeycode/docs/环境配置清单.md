# 环境配置清单

## 配置文件位置

项目内已有配置样例：

- `backend/.env.example`
- `frontend/.env.example`

真实环境变量应由本地 `.env`、服务器环境或进程管理器注入。文档和代码示例只保留变量名和占位符。

## 后端基础配置

| 变量 | 用途 | 默认或说明 |
| --- | --- | --- |
| `PORT` | Express 监听端口 | 默认 `3001` |
| `NODE_ENV` | 运行环境 | 生产环境应为 `production` |
| `GUEST_MODE` | 非生产 guest mode 开关 | 设置为 `false` 可关闭 |
| `LOG_LEVEL` | 日志级别 | 默认 `info` |
| `LOG_DIR` | 日志目录 | 默认当前工作目录下 `logs` |

后端入口 `backend/src/index.js` 会读取 `.env`，并监听 `0.0.0.0`。

## JWT 与登录

| 变量 | 用途 | 说明 |
| --- | --- | --- |
| `JWT_SECRET` | JWT 签名密钥 | 生产环境必填 |
| `JWT_EXPIRES_IN` | JWT 有效期 | 默认 `7d` |
| `INTERNAL_TEST_VERIFICATION_CODE` | 内测验证码 | 正式公开发布前清空 |

`JWT_SECRET` 缺失时，生产环境受保护接口无法通过鉴权。非生产 guest mode 可绕过 token 便于本地调试。

## MySQL

项目支持两套变量名，读取顺序在 `backend/src/models/db.js` 中定义。

| 首选变量 | 兼容变量 | 用途 |
| --- | --- | --- |
| `DB_HOST` | `MYSQL_HOST` | MySQL 主机 |
| `DB_PORT` | `MYSQL_PORT` | MySQL 端口 |
| `DB_NAME` | `MYSQL_DATABASE` | 数据库名 |
| `DB_USER` | `MYSQL_USER` | 数据库用户 |
| `DB_PASSWORD` | `MYSQL_PASSWORD` | 数据库密码 |

非生产环境连接失败会 fallback 到内存 mock DB。生产环境查询失败会抛错。

## Redis

| 变量 | 用途 | 说明 |
| --- | --- | --- |
| `USE_REAL_REDIS` | 是否连接真实 Redis | 值为 `true` 时启用 |
| `REDIS_URL` | Redis URL | 优先于 host |
| `REDIS_HOST` | Redis 主机或连接串 | 未配置 URL 时使用 |
| `REDIS_PORT` | Redis 端口 | 样例中保留 |
| `REDIS_PASSWORD` | Redis 密码 | 当前连接代码未显式读取 |

默认使用内存 mock Redis。验证码、临时缓存和本地调试可依赖 mock；线上建议使用真实 Redis。

## AI 网关

推荐项目侧变量：

| 变量 | 用途 |
| --- | --- |
| `USER_LLM_API_KEY` | 项目侧 AI Key |
| `USER_LLM_BASE_URL` | 项目侧 AI 服务 base URL |
| `USER_LLM_MODEL` | 项目侧模型名 |
| `AI_REQUEST_TIMEOUT` | AI 请求超时时间，单位毫秒 |

`backend/src/services/ai.js` 会请求 `{BASE_URL}/chat/completions`。新增 AI 功能时使用 `USER_LLM_*` 变量，避免把平台运行环境变量写入项目配置。

后端样例文件中保留历史兼容变量名。新部署和新文档应使用项目侧变量名。

## 知识库

| 变量 | 用途 | 默认或说明 |
| --- | --- | --- |
| `KB_ROOT_PATH` | 知识库根目录 | 开发环境常用 `../knowledge-base` |
| `KB_MAX_CONTEXT_CHARS` | 注入 prompt 的上下文上限 | 样例为 `4500` |
| `KB_MAX_FILE_CHARS` | 单文件读取字符上限 | 样例为 `1800` |
| `KB_VECTOR_TOPK` | 向量检索 topK | 样例保留 |
| `KB_RETRIEVAL_MODE` | 检索模式 | 样例为 `mapping_only` |

生产环境默认知识库路径在架构文档中记录为 `/home/ubuntu/woying-ai/knowledge-base`，可通过 `KB_ROOT_PATH` 覆盖。

## 支付与推荐

| 变量 | 用途 |
| --- | --- |
| `PAYMENT_CALLBACK_SECRET` | 支付回调签名密钥 |
| `FRONTEND_BASE_URL` | 前端基础地址 |
| `REFERRAL_BONUS_DAYS_PER_REFERRAL` | 每次推荐奖励天数 |
| `REFERRAL_COMMISSION_RATE` | 推荐佣金比例 |
| `REFERRAL_COMMISSION_COOLDOWN_DAYS` | 推荐佣金冷却天数 |

支付回调要求 `PAYMENT_CALLBACK_SECRET` 存在，并使用 HMAC SHA-256 校验签名。

## 定时任务

| 变量 | 用途 |
| --- | --- |
| `CRON_SECRET` | 定时任务接口访问密钥 |

定时任务路由挂载在 `/api/cron`。对外部署时应结合网关访问控制和密钥校验。

## 前端配置

`frontend/.env.example` 当前包含：

| 变量 | 用途 | 默认或说明 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | 前端 Axios baseURL | 默认 `/api` |
| `VITE_APP_TITLE` | 应用标题 | 样例为我赢AI |

开发服务器代理还读取 `VITE_API_TARGET`：

```bash
cd frontend
VITE_API_TARGET=http://localhost:3001 npm run dev
```

`frontend/vite.config.js` 已配置：

- `host: 0.0.0.0`
- `port: 5173`
- `allowedHosts: ['.monkeycode-ai.online']`
- `/api` 反向代理
- ECharts、Vue、工具目录等构建分包

## 小程序配置

小程序位于 `miniapp/`，使用 uni-app 和 Vite。

命令：

```bash
cd miniapp
npm run dev:mp-weixin
npm run build:mp-weixin
```

`miniapp/vite.config.js` 已配置 `allowedHosts: ['.monkeycode-ai.online']`。

## 发布前配置核对

发布前核对：

- `NODE_ENV` 为生产环境值。
- `JWT_SECRET` 已配置。
- MySQL 连接指向真实库。
- Redis 策略符合发布要求。
- `USER_LLM_*` 已由运行环境注入。
- `PAYMENT_CALLBACK_SECRET` 已配置。
- `INTERNAL_TEST_VERIFICATION_CODE` 已按发布阶段处理。
- `KB_ROOT_PATH` 指向线上知识库目录。
- 前端构建使用正确 API baseURL 或生产网关路径。
