- `https://woyai.cn/` 返回 HTTP 200，首页静态资源可访问。
- `https://woyai.cn/api/health` 返回 `status: ok`。
- Nginx、PM2 后端、MySQL 和 Redis 均处于运行状态。
- 服务器资源暂无明显容量压力。
- 线上目录不是 Git 仓库，且抽样的关键运行文件与当前本地仓库全部不一致。
- `/api/token-monitor/today` 与 `/api/token-monitor/dashboard` 未登录返回 HTTP 200，确认运维统计接口公开。
- `/api/admin/stats` 未登录返回 HTTP 401，基础鉴权生效；但代码仍把 annual 会员视为管理员，需使用真实 annual 账号另做授权回归。
- 线上 CORS 响应为 `Access-Control-Allow-Origin: *`。

## 2. 运行拓扑

```text
Internet
  -> Nginx :80/:443
     -> /              /home/ubuntu/woying-ai/frontend/dist
     -> /api           http://127.0.0.1:3000
  -> PM2 woying-backend
     -> Node.js 20.20.2 / Express production
     -> MySQL 127.0.0.1:3306
     -> Redis 127.0.0.1:6379
     -> 外部 AI 网关
```

服务器还承载其他进程、端口和域名。任何部署、重启或 Nginx 修改都必须限定影响范围，不能把整机当作我赢AI独占服务器。

## 4. 网络边界

- Nginx 对外监听 80/443。
- SSH 对外监听 22，应继续依赖云防火墙、密钥登录和最小权限控制。
- MySQL、Redis 仅监听回环地址。
- Node 后端监听 `0.0.0.0:3000`；公网直连测试超时，说明当前外层网络有阻断，但应用仍建议改为仅监听 `127.0.0.1`，减少对防火墙规则的依赖。
- 主站 `/api` 明确代理到 `127.0.0.1:3000`。当前源码默认端口 `3001` 与线上运行配置不同。

## 5. 版本一致性

抽样比较以下线上文件与当前本地工作区 SHA-256：

- `backend/src/index.js`
- `backend/src/routes/admin.js`
- `backend/src/routes/auth.js`
- `backend/src/routes/payment.js`
- `backend/src/routes/tokenMonitor.js`
- `backend/package.json`

结果：六个文件全部不同。该结果只证明版本存在漂移，不代表线上或本地任一方必然更新。下一次发布前必须先生成语义差异和依赖差异，不应直接用本地目录覆盖线上。

## 6. 已验证安全边界

| 检查项 | 结果 | 判断 |
| --- | --- | --- |
| 未登录访问 Token Monitor | HTTP 200 | P1，需立即加管理员鉴权或网关限制 |
| 未登录访问 Admin Stats | HTTP 401 | 匿名鉴权生效 |
| 任意 Origin 请求健康接口 | `Access-Control-Allow-Origin: *` | P1，应配置生产白名单 |
| 公网直连 Node 3000 | 超时 | 当前外层阻断有效，但应用监听范围仍过宽 |
| 私钥本地文件权限 | 已收紧为当前用户、SYSTEM、管理员 | 已降低本地凭据暴露风险 |

## 7. 建议优先级

1. 拆分 annual 会员与 admin 管理角色，并回归全部后台接口。
2. 封闭 `/api/token-monitor/*`，不要只隐藏前端入口。
3. 建立 release manifest 和不可变发布包，解决线上与仓库版本不可追溯问题。
4. 将生产 CORS 改为域名白名单，将 Node 监听地址改为回环地址。
5. 接入真实短信、微信支付和内容安全服务后再视为完整商业闭环。

## 8. 核查限制

- 未登录任何真实业务账号，因此没有验证 annual 用户的实际越权结果。
- 未读取数据库、Redis 数据、环境变量值或业务日志，避免接触用户数据和密钥。
- 未执行写操作、服务重启、部署、配置变更或压力测试。
- 浏览器扩展未连接，页面结论来自公开 HTTP 响应和代码分析；未进行逐页视觉验收。
