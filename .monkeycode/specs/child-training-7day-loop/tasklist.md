# 需求实施计划

> 作者：Monkeycode  
> 设计规格：`docs/superpowers/specs/2026-08-23-child-training-7day-loop-design.md`

- [x] 1. 建立四类匿名业务样本与统一测试协议
  - 在 `backend/scripts/fixtures/child-training-loop-fixtures.js` 建立获客不足、预约到店不足、到店不成交、续费不足四类样本。
  - 为每类样本定义预期主问题、必命中知识主题、预期指标和允许的降级状态。
  - 样本只使用聚合数据，不包含儿童姓名、电话、CRM明细或可识别个人信息。
  - [x] 1.1 增加样本属性测试：所有样本均不包含手机号/姓名字段，指标均为非负数，且至少有一个可计算漏斗指标。

- [x] 2. 实现统一业务诊断输入协议
  - 新增 `backend/src/services/acquisition/businessLoop.js`，定义 `problem_code`、课程、年龄段、城市、聚合指标和短描述的白名单及校验。
  - 将业务问题映射到对应 Skill、渠道和知识检索场景，用户不直接选择 Skill 或知识库。
  - 缺失字段不伪造比率；返回明确的数据不足项和可继续执行状态。
  - 保持现有 `createDiagnosis`、快照和旧渠道适配器兼容。
  - [x] 2.1 增加输入协议单元测试：问题枚举、非负指标、负数/个人字段/未知字段拒绝或过滤、零分母处理。

- [x] 3. 打通知识驱动诊断与统一结果卡
  - 扩展 `backend/src/services/acquisition/index.js` 或业务闭环服务，使用统一输入生成一个主问题、最多两个行动、数据证据、知识依据、排除动作、验证指标和停止条件。
  - 确保诊断结果记录知识 ID、证据级别、核验日期、`knowledgeStatus` 和 `needs_review`。
  - 未配置 LLM 或输出契约失败时进入人工复核，不伪造 AI 成功；在可用的规则层保留确定性诊断依据。
  - 修复和保持 `aiRunner` 敏感字段脱敏与知识命中审计。
  - [x] 3.1 增加四类样本诊断属性测试：不同输入不能全部返回同一主问题；每个结果最多两个行动且行动包含指标和停止条件。
  - [x] 3.2 增加知识命中测试：每类样本至少命中两条相关知识，冲突/过期/限制知识不进入结果。

- [x] 4. 改造老板端获客入口为最小表单
  - 修改 `frontend/src/views/growth/AcquisitionEngine.vue`，移除固定项目名称、固定目标和固定诊断文本。
  - 增加“本周最想解决的问题”选择器和最小聚合指标表单；高级指标折叠，空字段显示影响说明但允许继续。
  - 诊断提交后展示主问题、数据证据、知识依据、排除动作、人工复核状态和下一步行动。
  - 保持现有项目历史、机构请求头、错误重试和响应式布局。
  - [x] 4.1 增加前端协议测试或组件级测试（项目无现成前端测试框架，以生产构建和代码审查替代）：首次表单字段、提交禁用、缺失数据提示、敏感字段不出现在表单和诊断展示。

- [x] 5. 实现诊断到七天行动计划
  - 扩展前端增长 API 与后端行动计划接口，使诊断卡可一键保存行动计划。
  - 行动计划包含目标、负责人、截止日期、步骤、完成标准、验证指标、停止条件和执行状态。
  - 防止跨项目/跨机构诊断绑定，保留现有机构权限校验。
- [x] 5.1 增加行动计划契约测试（沿用既有跨项目/机构隔离测试，新增诊断动作继承逻辑）：最多两个优先动作、负责人/截止日期可追踪、跨机构访问拒绝、重复提交幂等或明确返回冲突。

- [x] 6. 实现七天后指标复盘与四态建议
  - 新增或扩展 `backend/src/services/growthReview.js`，支持录入下一周期聚合指标和行动完成状态。
  - 比较前后指标并只返回 `continue`、`adjust`、`stop`、`consultant` 之一，附变化证据和理由。
  - 数据不足、零分母、高风险隐私或投流风险时保持人工复核，不自动给出强制动作。
  - 在前端增加阶段数据录入、前后指标对比、复盘建议和顾问升级提示。
  - [x] 6.1 增加复盘属性测试：指标减少/不变/改善/缺失分别产生稳定四态结果，零分母不产生 Infinity 或 NaN。

- [x] 7. 运行闭环验收与回归检查
  - 扩展 `backend/scripts/core-business-loop.test.js`，覆盖四类匿名样本全链路：输入、知识、诊断、行动、复盘和顾问升级。
  - 运行 `node --test scripts/*.test.js`，确认既有机构、存储、异步、知识、Quick Plan 和增长回归不受影响。
  - 运行 `cd frontend && npm run build`，确认获客页面和响应式入口构建通过。
  - 记录 Mock DB、LLM 未配置和未部署限制，不将规则测试结果表述为真实模型质量验证。
