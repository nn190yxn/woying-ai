# Requirements Document

## Introduction

本规格定义我赢AI全站设计排版系统重构。重构目标是在不调整业务内容主线的前提下，将当前页面从分散的卡片拼贴和文档式堆叠，收口为适合本地生活老板高频使用的工作台式体验。系统需要统一视觉层级、页面栅格、导航定位、卡片密度、表单与结果区布局、响应式规则和组件状态表达。

## Glossary

- **工作台式体验**: 以任务、指标、行动入口和复盘结果为主线的产品界面形态。
- **页面框架**: 页面级标题、导航、内容容器、主次栏位、操作区和响应式布局规则的组合。
- **设计令牌**: 前端 CSS 变量中定义的颜色、字号、行高、间距、圆角、阴影和断点。
- **任务页**: 需要用户输入、生成、保存、执行或复盘的页面，包括诊断、计划、复盘和工具执行页。
- **Hub 页面**: 抖音、小红书、私域等专项入口页面。
- **信息密度**: 单屏内容中可阅读和可操作信息的数量与布局舒适度。

## Requirements

### Requirement 1

**User Story:** AS 本地生活老板, I want 全站页面像经营工作台一样组织信息, so that 我可以快速知道当前页面要完成的任务、关键指标和下一步动作。

#### Acceptance Criteria

1. WHEN 用户进入首页、工具页、会员页、任一 Hub 页面或任务页, the 前端 SHALL 展示统一的页面标题区，标题区包含页面任务、辅助说明和主操作入口。
2. WHEN 页面包含经营任务链路, the 前端 SHALL 按照“当前任务 -> 关键依据 -> 执行动作 -> 复盘指标”的顺序组织主要内容。
3. WHEN 页面展示多个入口或工具, the 前端 SHALL 使用统一的卡片密度和状态标签表达入口优先级、会员权限和可用状态。
4. WHILE 用户浏览桌面端页面, the 前端 SHALL 在首屏内展示当前页面的主任务和至少一个明确主操作。

### Requirement 2

**User Story:** AS 用户, I want 页面排版层级清楚, so that 我可以在 10 秒内扫读出重点内容。

#### Acceptance Criteria

1. WHEN 页面渲染标题、模块标题、正文、说明和标签, the 前端 SHALL 使用统一字号、字重和行高层级。
2. WHEN 页面展示长文本或依据说明, the 前端 SHALL 将内容拆分为摘要、分组卡片、键值项或列表，避免单一大卡片承载全部信息。
3. WHEN 页面展示原始数据或指标, the 前端 SHALL 使用指标卡、键值表或表格结构表达数据。
4. WHILE 页面存在多段内容, the 前端 SHALL 使用统一模块间距和区块节奏区分内容层级。

### Requirement 3

**User Story:** AS 用户, I want 全站导航和页面定位稳定, so that 我知道自己位于哪个经营环节，并能快速切换到相关页面。

#### Acceptance Criteria

1. WHEN 用户访问全站主页面, the 前端 SHALL 保持全局导航项与经营任务链路一致。
2. WHEN 用户访问任务页, the 前端 SHALL 展示返回路径、当前页面任务和可关联的下一步入口。
3. WHEN 页面内容长度超过两个主要区块, the 前端 SHALL 提供页面内定位能力，例如锚点导航、阶段导航或分组标签。
4. WHEN 用户在移动端访问全局导航, the 前端 SHALL 以可触控菜单展示完整导航和登录入口。

### Requirement 4

**User Story:** AS 用户, I want 计划、复盘和诊断页面的卡片布局适合阅读和操作, so that 我可以按天执行、记录数据并查看结论。

#### Acceptance Criteria

1. WHEN 用户查看 15 天计划页, the 前端 SHALL 避免窄列竖卡挤压中文内容，并将每日任务拆成可扫读的主内容、工具区和复盘区。
2. WHEN 用户查看复盘页, the 前端 SHALL 将输入项、核心指标、诊断结论和下一步建议分为清晰的工作台区块。
3. WHEN 用户查看诊断结果页, the 前端 SHALL 突出主短板、诊断依据、行业基准、风险边界和推荐动作。
4. WHEN 页面包含主按钮和次按钮, the 前端 SHALL 使用一致的按钮层级、尺寸和状态表达操作优先级。

### Requirement 5

**User Story:** AS 用户, I want 全站在桌面、平板和手机上都可用, so that 我可以在不同设备上完成经营任务。

#### Acceptance Criteria

1. WHEN 视口宽度大于等于 1200px, the 前端 SHALL 使用稳定的桌面栅格承载主内容、辅助信息和操作区。
2. WHEN 视口宽度在 768px 到 1199px 之间, the 前端 SHALL 将三栏内容降级为两栏或主内容优先布局。
3. WHEN 视口宽度小于 768px, the 前端 SHALL 将页面组织为单列布局，并保证主操作按钮可触达。
4. IF 文本、按钮、表格或卡片内容超过容器宽度, the 前端 SHALL 通过换行、折叠、分组或容器内滚动保持页面级宽度稳定。

### Requirement 6

**User Story:** AS 开发者, I want 可复用的前端布局和组件规范, so that 后续页面可以持续保持一致的工作台体验。

#### Acceptance Criteria

1. WHEN 开发者新增或调整页面, the 前端 SHALL 提供可复用的页面框架、区块标题、指标卡、任务卡、操作面板和状态标签样式。
2. WHEN 开发者调整设计令牌, the 前端 SHALL 通过集中 CSS 变量影响全站同类组件。
3. WHEN 页面使用卡片、按钮、标签、表单和 Tab, the 前端 SHALL 复用统一基础类或共享组件。
4. WHEN 开发者运行结构检查, the 前端 SHALL 能验证关键页面存在统一布局锚点和响应式约束。
