# 本地生活知识操作系统实施任务清单

> 作者：Monkeycode  
> 依据：`docs/superpowers/specs/2026-08-22-local-life-knowledge-os-design.md`  
> 范围：完成必要开发与测试，不部署、不迁移线上数据。

- [x] 1. 知识治理底座与数据模型
  - [x] 1.1 新增只读清单冻结工具，输出相对路径、类型、大小、SHA-256、处理状态，并排除隐藏工具目录、脚本、配置、压缩包、凭证和工作记忆。
  - [x] 1.2 实现JSON字段白名单、路径安全和敏感信息脱敏，禁止Token、签名URL、联系方式、用户ID、IP及儿童/家长身份信息进入产品知识层。
  - [x] 1.3 建立原始证据、知识对象、产品规范版本、派生/冲突关系、审核记录的数据模型与索引，并同步Mock DB。
  - [x] 1.4 实现幂等兼容建表/补列，不覆盖现有知识映射、获客项目、销售Skill和私有资产。
  - [x] 1.5 编写冻结清单、哈希、排除、白名单、路径穿越、脱敏、Mock DB与迁移测试。
  - [x] 1.6 检查点：确认清单可复现、敏感数据不入库、迁移幂等。

- [x] 2. 首批儿童培训结构化知识口径
  - [x] 2.1 实现知识对象校验、审核、发布、替代、撤回、归档、冲突和过期生命周期。
  - [x] 2.2 建立儿童培训统一经营漏斗及五类瓶颈诊断规则。
  - [x] 2.3 建立抖音、小红书、体验课货盘、内容行动卡和小额投流实验口径。
  - [x] 2.4 限制餐饮、团购、医美等跨行业材料只能作为低优先级类比。
  - [x] 2.5 编写字段完整性、规范版本唯一性、冲突发布、高变化标记、行动卡和禁止投流测试。
  - [x] 2.6 检查点：确认知识可追溯、动态知识有复核期、冲突/跨行业知识不能生成强制动作。

- [x] 3. 结构化检索与知识生命周期
  - [x] 3.1 重构 `kbService.js`，用结构化知识索引替代硬编码文件列表，同时保留旧接口与上下文预算。
  - [x] 3.2 实现行业、产品域、渠道、场景、知识类型、证据等级、时效、状态、Skill版本和机构范围过滤。
  - [x] 3.3 实现机构基线优先排序、派生链去重和过期自动降级。
  - [x] 3.4 默认隔离冲突、撤回、过期、归档和高隐私知识；输出不得包含受限原文。
  - [x] 3.5 编写过滤、排序、去重、降级、冲突隔离、字符上限和旧接口兼容测试。
  - [x] 3.6 检查点：确认机构隔离、私有边界和旧工具不回退。

- [x] 4. Skill体系与统一AI Runner
  - [x] 4.1 注册经营漏斗、抖音、小红书、货盘、内容计划、投流实验、周复盘和顾问升级Skill并定义版本化输出契约。
  - [x] 4.2 增强输出校验，覆盖诊断证据、行动卡、验证指标、停止条件、预算边界、知识状态和顾问触发。
  - [x] 4.3 扩展AI Runner的脱敏、机构基线、结构化检索、运行审计和失败归类。
  - [x] 4.4 重构获客诊断，移除直接模型调用并统一进入AI Runner；OCR结果作为需人工确认的受限输入。
  - [x] 4.5 编写Skill兼容、Runner脱敏、知识上下文、渠道路由、OCR限制和禁止直调模型测试。
  - [x] 4.6 检查点：确认获客诊断统一经过AI Runner，非法输出进入 `needs_review`。

- [x] 5. 指标、机构基线与周复盘
  - [x] 5.1 扩展有效线索、到店、体验、正价报名、回款、成本和转化率聚合指标。
  - [x] 5.2 实现白名单、非负校验、零分母处理、派生指标及禁止个人客户明细。
  - [x] 5.3 实现机构/项目/渠道阶段基线和前后对比，机构实测优先于通用阈值。
  - [x] 5.4 实现周复盘，只输出一个下周首要问题，并保存知识版本、基线和停止条件。
  - [x] 5.5 同步Mock DB并编写指标、公式、基线优先、阶段对比和唯一问题测试。
  - [x] 5.6 检查点：确认快照仅含聚合数据、周复盘输出唯一优先事项。

- [x] 6. 顾问触发与服务交付
  - [x] 6.1 实现连续行动无改善、预约到店异常、到店成交异常、预算利润不清、续费跨域下降、数据矛盾及隐私安全风险触发。
  - [x] 6.2 输出原因、证据、严重度、服务类型、人工确认项和去重键，并接入服务告警去重、关闭和重开。
  - [x] 6.3 映射经营诊断、30天计划、周复盘、货盘/内容/到店/续费评审服务建议。
  - [x] 6.4 扩展顾问摘要；高风险问题强制人工接管，禁止AI自动承诺。
  - [x] 6.5 编写触发、连续周期、告警幂等重开、服务映射、顾问权限和人工接管测试。
  - [x] 6.6 检查点：确认全部强制触发可追溯，未分配顾问不可访问。

- [x] 7. API与前端最小闭环
  - [x] 7.1 扩展获客API和前端API，支持诊断类型、周复盘、扩展指标、知识依据和顾问触发。
  - [x] 7.2 更新获客页，展示现象、证据、原因、行动卡、验证指标、停止条件、依据类型、核验日期和人工复核状态。
  - [x] 7.3 增加聚合指标录入、阶段快照和周复盘展示，不提供个人客户或CRM入口。
  - [x] 7.4 更新顾问、成果和服务页面，展示告警证据、服务建议、阶段变化和介入摘要，不展示受限原文。
  - [x] 7.5 完善加载、空、失败、人工复核、过期、冲突和无权限状态及响应式布局。
  - [x] 7.6 编写API权限、敏感字段缺失、周复盘唯一问题、顾问展示和前端构建测试。
  - [x] 7.7 检查点：客户侧无第三方原文、CRM或个人明细，前端构建通过。

- [x] 8. 兼容迁移与全量验收

  - [x] 8.2 执行知识验收：原文不默认注入、知识可追溯、动态过期降级、冲突不触发、高敏零泄露。
  - [x] 8.3 执行业务与边界验收：诊断结构完整、机构数据优先、周复盘唯一问题、顾问触发覆盖、无CRM和收益承诺。
  - [x] 8.4 运行增长、媒体、渠道、顾问、Quick Plan、Mock DB、API和前端构建回归。
