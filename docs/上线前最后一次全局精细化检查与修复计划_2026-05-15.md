# 上线前最后一次全局精细化检查与修复计划（2026-05-15）

## 1. 目标

- 对当前版本做最后一次上线前全局检查。
- 在不扩大结构改造范围的前提下，完成最后一轮高价值修复计划制定。
- 保证后续执行具备三项能力：可备份、可回测、可回滚。

## 2. 当前总体判断

- 当前版本已经达到可内测上线状态。
- 当前版本的主干能力已经稳定：统一外层协议、知识库主干接入、访客模式、核心路由结构、线上部署与基础验收均已打通。

- 最后一轮精细化修复应坚持“小步、可控、逐项验证”的策略，不再做全站级重构。

## 4. 风险分级结论

### P0

- 当前无新的阻断上线型 P0。
- 已完成的 P0 修复包括：
  - 抖音专项 `result.result` 双层嵌套收口
  - JWT secret 获取口径统一

### P1

- `generate` 工具存在一批 `degraded=true`，当前主因是输入协议缺参触发 failover。
- `privateAgents.js` 仍保留少量本地目录读取和内容旁路，虽已持续收口，但还未完全迁入统一 `kbService` 内容供给。
- 统一协议当前是兼容统一，不是最终单一领域载荷规范。

### P2

- AI 工具、RAG 工具、规则工具的最终执行抽象仍有历史分支。
- 前端少数页面仍依赖历史顶层字段兼容层。

## 5. 最后一次修复总原则

- 只做高收益、低扩散、可验证的修复。
- 所有线上操作先备份，后变更，再回测。
- 所有修复必须有明确“成功标准”和“回滚条件”。
- 所有回测优先使用现有 smoke、健康检查、核心接口抽测和日志复核。
- 单次修复包内控制变量，避免把架构收口和功能变更混在一起。

## 6. 最后一轮修复批次设计

### 批次 A：输入协议全局治理

#### 目标

- 将当前线上 `degraded=true` 的生成类工具，优先按输入协议错位进行统一治理。

#### 当前证据

- 最新线上日志显示，以下工具明确因缺参触发降级：
  - `marketing-budget`
  - `retention-rate`
  - `churn-rate`
  - `ltv-education`
  - `promotion-profit`
- 同类现象还出现在多批经营分析/行业测算工具中。

#### 修复方法

1. 以 `CALCULATORS.inputs` 为唯一输入协议基线。
2. 对照前端表单提交字段。
3. 对照 `smoke` 和 `deep-test` payload。
4. 对 `generate.js` 中必要的 payload normalize 做最小补齐。
5. 对确实缺字段的前端表单补默认值或字段映射。

#### 成功标准

- 目标工具在本地与线上抽测时不再因“缺少必要参数”进入 failover。
- 对应工具 `degraded=false` 或至少不再走“参数缺失型降级”。

#### 回滚条件

- 任一修复导致原本可用工具返回 4xx/5xx。
- 任一修复导致原有 `smoke` 核心接口失败。

### 批次 B：私域知识库旁路继续收口

#### 目标

- 继续压缩 `privateAgents.js` 中剩余的目录扫描、文档筛选和片段提取旁路。

#### 当前状态

- 已完成：
  - `loadKB()` TTL 缓存
  - `summarizePrivateKbLibrary()`
  - `getPrivateKbDoc()`
  - `extractSnippet()`
  - `hasSnippetKeyword()`
  - `getIndustrySceneDocs()`
  - `parseMarkdownTableMap()`

#### 修复方法

1. 盘点仍直接依赖 `kb.theory / kb.scenes / kb.sops / kb.scripts` 的点位。
2. 优先提炼为模块内共享函数。
3. 第二优先级再考虑迁到 `kbService` 统一内容供给。
4. 维持现有返回结构和业务文本行为稳定。

#### 成功标准

- `privateAgents.js` 中内容读取点数量继续下降。
- 语法检查通过。
- 私域核心接口结构不变、摘要不空、关键字段不空。

#### 回滚条件

- 私域任一核心接口出现空结果、结构缺失或关键建议文本断裂。

### 批次 C：统一结果协议与页面消费复核

#### 目标

- 保证核心页面仍能消费双层兼容结构，不因最后一次修复断裂。

#### 修复方法

1. 抽查小红书、抖音、私域、生成类工具各 3 个接口。
2. 核对 `status/degraded/summary/meta/result`。
3. 核对前端关键页面对 `top-level` 与 `result.*` 的消费路径。
4. 保持“兼容优先”的修复策略。

#### 成功标准

- 不再出现新的结构分叉。
- 不再出现 `result.result.*`。

#### 回滚条件

- 任一核心页面渲染异常。
- 任一接口结构与当前线上验收基线不一致。

## 9. 回滚策略

### 9.1 代码回滚

- 使用最近一次部署前备份包回滚整个项目目录。

```bash

```

### 9.2 环境回滚

- 使用 `.env.backup.<timestamp>` 回滚。

### 9.3 回滚触发条件

- 健康检查失败。
- `smoke:core` 任一核心接口失败。
- 本次修复引入新的结构断裂。
- 日志中出现连续性 5xx 或大面积 401/403。
