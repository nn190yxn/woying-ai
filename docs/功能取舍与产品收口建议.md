# 功能取舍与产品收口建议

## 结论

当前产品能力储备已经足够，下一阶段重点是收口展示和经营闭环。前台应从“工具集合”改为“本地生活老板的 AI 经营诊断与增长作战系统”。

核心路径建议固定为：

```text
经营体检 -> 诊断结论 -> 15 天作战计划 -> 内容/话术/投流/私域动作 -> 每日复盘
```

## 现状规模

- 普通工具池：107 个。
- 独立专项能力：4 个。
- 表格模板：57 张。
- 抖音专项前端页面：17 个。
- 小红书专项前端页面：17 个。
- 私域专项前端页面：17 个。

这个规模适合后台保留能力，前台按经营任务强收口。用户首屏看到的重点应是“今天先诊断什么、接下来做什么、如何复盘”。

## 功能分层

### 第一层：主入口能力

这些能力应出现在首页、导航和会员权益核心位置。

| 能力 | 当前入口 | 建议动作 | 原因 |
| --- | --- | --- | --- |
| 抖音经营体检 | `/douyin/diagnosis` | 保留并强化 | 已完成知识库、模型、规则底稿、行业基准和回归测试，适合作为标杆闭环 |
| 小红书账号体检 | `/xhs/account-diagnosis` | 保留并升级 | 与抖音体检结构相似，可复制“诊断依据 + 置信度 + 作战计划”机制 |
| 私域运营体检 | `/private/diagnosis` | 保留并升级 | 私域是转化与复购承接层，和抖音/小红书天然互补 |
| 15 天计划 | `/douyin/quick-plan`、`/xhs/quick-start-plan` | 保留并打通诊断结果 | 这是从报告到行动的关键付费理由 |
| 90 天战略 | `/douyin/full-strategy`、`/xhs/growth-strategy`、`/private/full-strategy` | 保留为高阶权益 | 适合作为年度会员和专家服务入口 |
| 数据复盘 | 抖音/小红书/私域数据诊断类页面 | 保留并合并成复盘中心 | 建立持续使用习惯 |
| 专家升级 | 现有预约文案 | 保留并统一入口 | 承接高客单服务 |

### 第二层：诊断后的推荐工具

这些工具应从主入口降级为“报告推荐动作”，由诊断结果触发。

| 工具类型 | 包含能力 | 建议动作 | 推荐触发场景 |
| --- | --- | --- | --- |
| 内容生产 | 标题、钩子、脚本、选题、封面、小红书正文 | 合并到内容成交工具组 | 低播放、低互动、内容供给不足 |
| 转化话术 | 卖点提炼、成交话术、评论/私信/企微话术 | 合并到成交承接工具组 | 播放高但咨询少、咨询高但成交少 |
| 投流判断 | ROI、DOU+、本地推、聚光、渠道 CAC | 合并到投流评估工具组 | 已有自然流量基础或付费成本异常 |
| 私域动作 | 社群 SOP、复购留存、会员设计、裂变计划 | 合并到私域承接工具组 | 到店或私信后复购弱、客户沉睡、转介绍少 |
| 经营计算 | 毛利、盈亏、现金流、人效、回本周期 | 合并到经营计算中心 | 诊断涉及成本、利润、人效或投资决策 |

### 第三层：经营数据与表格资产

57 张表格模板应作为“经营数据输入层”和“复盘留存层”，集中进入经营数据表体系。

建议重命名为“经营数据表”，并按使用场景展示：

| 场景 | 代表模板 | 产品定位 |
| --- | --- | --- |
| 每日记录 | 每日营收记录表、服务排期表、课程排期表 | 帮老板形成复盘数据 |
| 客户管理 | 客户信息登记表、会员管理表、沉睡客户相关表 | 支撑私域分层和复购 |
| 成本利润 | 食材成本、菜单毛利、项目消耗、库存盘点 | 支撑利润诊断和定价 |
| 营销复盘 | 活动 ROI、渠道对比、转介绍追踪、推广预算 | 支撑获客效率判断 |
| 团队管理 | 员工考勤、教练业绩、美容师业绩 | 支撑人效和薪酬判断 |

### 第四层：模板库与低频方案

这些能力适合保留在二级入口“经营资料库”或“模板库”。

| 能力 | 建议动作 | 原因 |
| --- | --- | --- |
| 节日营销策划 | 收进模板库 | 节点型需求，使用频率低 |
| 周年庆活动方案 | 收进模板库 | 活动型需求，难形成日常闭环 |
| 淡季引流方案 | 收进模板库 | 可作为诊断后的补充资料 |
| 新店开业策划 | 收进模板库 | 生命周期场景，适合作为二级入口 |
| 降价促销方案 | 收进模板库 | 容易强化低价导向，应放在经营策略之后 |
| 团队培训方案 | 收进模板库 | 适合作为制度管理材料 |
| 投诉处理方案 | 收进模板库 | 低频应急场景 |
| 商业计划书生成器 | 收进资料库或重做 | 当前表达偏项目文档，和日常经营闭环距离较远 |

主线保留：

- 行业体检表。
- 15 天速胜计划。

- 组品定价助手。
- 转化链路优化。
- 本地推策略生成。

辅助保留：

- 爆款选题库。
- 脚本生成器。
- 标题优化器。
- 封面文案助手。

私域前端页面数量多于后端核心端点，建议先做入口清理。

主线保留：

- 私域运营体检表。
- 会员体系设计器。
- 复购留存方案。
- 社群运营 SOP。
- CAC vs LTV 分析。

- 前台主入口展示 6 个核心能力，其余入口从体检报告或动作库进入。

## 页面收口建议

### 首页

首页首屏建议改为三件事：

1. 开始经营体检。
2. 查看我的作战计划。
3. 记录今天的数据。

保留能力数量作为辅助信任信息，弱化“100+ 能力”和“功能分类”的主视觉权重。

### 工具页

当前工具页已经偏向“表格中心”，建议进一步明确为“经营数据表”。

页面结构建议：

1. 经营数据表。
2. 诊断后推荐工具。
3. 专项模块入口。
4. 全部能力索引。

### 会员页

会员页应从“权限说明”改为“经营结果权益”。

建议权益表达：

| 层级 | 核心卖点 |
| --- | --- |
| 免费版 | 完成基础体检和少量内容/计算体验 |
| 初阶版 | 获得 15 天执行计划和高频内容工具 |
| 进阶版 | 获得数据复盘、转化优化和投流评估 |
| 高阶版 | 获得 90 天战略、老板 IP 和专家升级通道 |

权限表可以保留，放到页面下半部分，让用户先看到经营结果权益。

### 导航

建议导航从工具分类改为经营任务：

- 经营体检。
- 作战计划。
- 内容成交。
- 数据复盘。
- 经营数据表。
- 会员服务。

## 实施顺序

## 实体店老板视角补充

后续重构应围绕一个更容易打动老板的主卖点推进：

```text
每天给你一张老板能照着做的经营作战表。
```

老板最关心的不是工具数量，而是三件事：哪里亏钱、今天该干什么、干完能否带来更多客流和成交。因此所有页面、报告和会员转化文案都应优先回答这三个问题。

### 核心吸引点

| 吸引点 | 产品表达 | 开发落点 |
| --- | --- | --- |
| 15 天作战计划表 | 每天告诉老板拍什么、怎么拍、怎么转化、看什么数据 | 抖音 15 天计划升级为表格型执行计划 |
| 老板今日任务 | 登录后直接看到今天要做的 3-5 个动作 | 首页或用户中心增加今日任务区 |
| 样例计划表 | 首页展示一张餐饮/美业/教培样例计划，让用户一眼看懂价值 | 首页新增“15 天作战表示例”模块 |
| 诊断像医生报告 | 少废话，多结论、依据、风险和动作 | 体检报告统一输出主短板、诊断依据、置信度、行业基准 |
| 不懂运营也能做 | 用户只填数据，系统每天给动作 | 表单、计划和工具之间自动带入上下文 |
| 结果看板 | 展示已执行天数、已发布视频、咨询数、成交数和有效内容类型 | 数据复盘中心增加经营结果概览 |

### 15 天计划表字段要求

15 天计划应采用表格型作战计划，而不是长文本方案。建议字段如下：

| 字段 | 说明 |
| --- | --- |
| 天数 | 第 1 天到第 15 天 |
| 阶段 | 定位测试、内容放大、成交优化 |
| 今日目标 | 当天要解决的经营问题 |
| 作品类型 | 故事型、干货型、打卡型、广告型、情景剧型 |
| 视频功能 | 立人设、做信任、拉互动、促咨询、推团购 |
| 拍摄方式 | 口播、VLOG、情景剧、现场记录、对话演绎 |
| 选题方向 | 当天内容主题 |
| 执行工具 | 一键生成脚本、标题、封面、评论引导、私信话术 |
| 投流计划 | 是否投放、预算、目标和评估口径 |
| 客户培育 | 评论、私信、企微、社群、回访动作 |
| 复盘指标 | 播放、完播、评论、私信、咨询、核销、成交 |
| 任务状态 | 未开始、进行中、已完成、已复盘 |

### 体验验收标准

每个阶段开发完成后，除技术验收外，还需要用老板视角做体验验收：

| 验收问题 | 达标标准 |
| --- | --- |
| 老板能否 10 秒内知道从哪里开始 | 首页首屏有明确“开始经营体检”或“查看今日任务”入口 |
| 老板能否看懂系统为什么这样判断 | 体检报告展示数据依据、行业基准和置信度 |
| 老板能否立刻执行 | 计划表每天都有明确任务和工具按钮 |
| 老板能否知道执行效果 | 复盘页展示播放、咨询、成交、投流 ROI 等结果指标 |
| 老板能否理解会员价值 | 会员页用经营结果表达权益，而不是只列功能权限 |

### 对开发规划的调整

原开发顺序保留，但每一阶段增加老板视角目标：

| 阶段 | 原目标 | 新增老板视角目标 |
| --- | --- | --- |
| 第 1 批：前台展示收口 | 首页、工具页、会员页文案和结构调整 | 首页必须突出“每天一张经营作战表”和样例计划表 |
| 第 2 批：专项模块排序 | 抖音、小红书、私域按体检到复盘排序 | 每个模块都让老板看到“先测、再做、再复盘”的路径 |
| 第 3 批：报告联动 | 体检报告推荐对应工具 | 报告必须像医生诊断，展示主短板、依据和下一步动作 |
| 第 4 批：会员转化 | 重写会员权益和升级提示 | 会员价值必须落到计划、工具、复盘和专家校准 |
| 第 5 批：计划表中枢 | 新增或升级 15 天计划表 | 每天任务可执行、可调用工具、可填写复盘数据 |
| 第 6 批：结果看板 | 建立复盘中心 | 展示执行天数、内容产出、咨询、成交和有效内容类型 |

### 推荐优先开发样板

第一条样板链路建议选抖音：

```text
抖音经营体检 -> 15 天短视频作战表 -> 每日脚本/标题/投流/私信工具 -> 视频与成交数据复盘 -> 下一轮计划
```

抖音体检当前专业度和回归测试基础最好，适合作为全站闭环标杆。打通后，小红书和私域按同一结构复制。

### 第 1 批：前台展示收口

- 改首页主文案和 CTA。
- 首页模块从 8 个分类改为 3 个主任务入口。
- 工具页标题从“经营表格统一收口”调整为“经营数据表与工具库”。
- 会员页首屏改成经营权益表达。

### 第 2 批：专项模块排序

- 抖音 Hub 改为“体检 -> 计划 -> 执行 -> 复盘”顺序。
- 小红书 Hub 改为同样的路径。
- 私域 Hub 主入口只展示 6 个核心能力，其余能力进入动作库。

### 第 3 批：报告联动

- 抖音体检报告根据 `diagnosticProfile` 推荐对应工具。
- 小红书体检增加诊断依据、置信度和推荐动作。
- 私域体检增加最低维度、推荐动作和下一步计划入口。

### 第 4 批：会员转化

- 会员页按经营结果重写权益。
- 诊断报告里的升级提示按问题类型展示。
- 高阶会员统一承接 90 天战略和专家服务。

## 当前推荐动作

先做第 1 批。它主要改前端展示和文案，风险最低，也能最快让产品从“工具箱”转向“经营系统”。
