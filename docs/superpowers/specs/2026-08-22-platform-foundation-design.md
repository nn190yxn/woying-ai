# 平台基础能力分阶段设计

> 作者：Monkeycode  
> 日期：2026-08-22  
> 范围：机构权限、服务器文件存储、异步任务可靠性。  
> 原则：先完成服务器可运行版本，保留替换云服务的边界；不接入 OSS/S3/Redis，不部署、不迁移线上数据。

## 1. 目标与边界

平台运行在服务器上。本阶段把文件保存到服务器磁盘，把耗时任务交给同一台服务器上的独立 Node Worker 进程处理。API 进程负责请求、鉴权和任务提交，不直接承担长时间任务。

必须保持：

- 机构之间数据隔离；
- MySQL 与 Mock DB 行为兼容；
- 现有获客、销售、服务、知识和私有资产接口兼容；
- 不引入 CRM、个人客户明细或自动营销；
- 不把源知识库内容暴露给客户；
- 所有新增能力均可测试、可关闭、可追溯。

## 2. 分阶段实施

### 阶段一：机构权限闭环

新增统一机构权限判断：

- `owner`：机构全部管理权限；
- `principal`：机构经营配置、成员查看和业务数据管理；
- `marketing_lead`：获客、内容和营销相关业务操作；
- `advisor`：被分配机构的诊断、复盘和服务查看，不得管理成员和删除资产；
- `platform_admin`：平台运维权限，但默认不绕过机构归属校验。

新增能力：

- 机构成员列表、添加/邀请、角色变更、移除；
- 默认机构切换；
- 机构网点增删改查；
- 角色级路由保护；
- 成员移除后立即失去机构资源访问权；
- 关键成员和权限变化记录审计事件。

安全规则：机构 ID 只来自服务端校验后的成员关系，不能仅信任请求体；顾问访问必须同时满足机构归属和服务分配关系。

### 阶段二：服务器文件存储闭环

建立 `StorageAdapter` 边界，当前提供服务器磁盘实现：

- 元数据仍保存数据库；
- 二进制文件保存到环境变量指定的存储根目录；
- 物理路径由服务端生成，不使用用户传入路径；
- 存储键包含机构隔离信息，但不直接暴露真实磁盘路径。

上传规则：

- 白名单 MIME 类型；
- 扩展名与 MIME 基本匹配；
- 最大文件大小；
- 实际上传大小与声明值一致；
- SHA-256 校验；
- 音视频时长暂不做本地解析，保留人工确认/供应商扩展点；
- pending 上传失败可清理，不产生长期孤儿记录。

访问规则：

- 签名内容包含资产 ID、机构 ID、过期时间和用途；
- 读取时校验签名、机构、状态、过期时间和物理文件存在性；
- expired、deleted、failed 资产不可读取；
- 删除操作要求机构管理角色或资产负责人；
- 增加过期扫描和物理文件清理服务。

未来接入 OSS/S3 时，只替换适配器，不修改业务路由和资产元数据契约。

### 阶段三：异步任务可靠性闭环

保留现有任务表与任务 API，增强任务状态机：

- `queued` → `processing` → `succeeded`；
- `processing` → `failed_retryable` → `queued`；
- 任意可取消状态 → `cancelled`；
- 失败达到上限后进入 `failed`。

可靠性机制：

- 数据库原子 claim，避免多个 Worker 重复执行；
- `locked_by`、`locked_at`、租约超时和僵尸任务恢复；
- 取消令牌与状态条件更新，取消后不得覆盖为成功；
- 指数退避和 `next_run_at`；
- handler 通过受控回调更新进度；
- 多进程幂等键冲突时重新读取已有任务；
- 业务结果使用结果幂等键，避免重试重复写入；
- 新增独立 Worker 入口，和 API 同机运行但进程隔离；
- 不开放任意任务类型提交，只允许注册表中的任务处理器。

## 3. 数据与兼容

数据库新增字段采用幂等补列方式，不覆盖现有数据。Mock DB 同步实现新增查询、更新和唯一约束语义。旧接口继续返回兼容字段，新记录使用增强结构。

所有机构、文件、任务查询必须带机构范围。跨机构请求统一返回无权限或资源不存在，不暴露资源是否存在的额外信息。

## 4. 测试验收

阶段一：

- 五类角色允许/拒绝矩阵；
- 成员添加、角色变更、移除后的访问回收；
- 默认机构切换；
- 网点隔离；
- 顾问分配权限；
- 跨机构访问拒绝。

阶段二：

- MIME、扩展名、大小和哈希校验；
- 路径穿越防护；
- 签名跨机构访问拒绝；
- 过期和删除不可读；
- 到期清理；
- 上传失败和 pending 回收；
- 存储适配器契约测试。

阶段三：

- 多 Worker 只 claim 一次；
- 取消与执行竞态；
- 重试上限和退避；
- 租约超时恢复；
- 进度回调；
- 多进程幂等提交；
- 业务结果唯一写入；
- Worker 自然退出和 API 回归。

## 5. 实施顺序

1. 先增加权限服务和角色中间件，再接入机构、存储、任务路由；
2. 再抽象存储适配器，补齐上传和签名安全；
3. 最后改造任务状态、数据库字段和独立 Worker；
4. 每阶段完成后运行专项测试，再运行全量回归和前端构建；
5. 未通过的边界测试不得标记阶段完成。
