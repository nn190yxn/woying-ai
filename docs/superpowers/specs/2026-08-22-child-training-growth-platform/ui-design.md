# 儿童素质培训老板AI平台 UI设计规格

> 作者：Monkeycode  
> 设计日期：2026-08-22  
> 状态：视觉方向与关键页面已获用户确认  
> 关联架构：`design.md`

## 1. 设计目标

UI服务于不一定每天登录系统的儿童素质培训机构老板、校长和市场负责人。界面应在短时间内回答：

1. AI获客引擎和AI销售教练分别能解决什么；
2. 用户上次进行到哪里；
3. 当前最重要的问题是什么；
4. 下一步应该执行什么；
5. 什么情况下需要人工陪跑。

产品不是CRM和员工管理系统，界面不得呈现复杂客户列表、销售管道、排课表或高密度经营后台。

## 2. 已确认视觉方向

采用“A｜温暖专业”：

- 气质：专业、可信、克制、有人情味；
- 适配：儿童素质培训行业与“软件＋陪跑服务”；
- 避免：过度童趣、廉价教育模板、深色赛博科技感、通用蓝白SaaS模板；
- 关键词：墨绿、米白、暖金、自然留白、清晰行动。

## 3. 设计令牌

### 3.1 色彩

```text
品牌深绿       #173D2C  主导航、重点背景
品牌行动绿     #1E563A  主按钮、关键链接
浅绿背景       #DFF1E5  获客引擎强调卡、选中状态
页面米白       #F5F3EC  页面背景
内容白         #FFFFFF  卡片和表单
暖金           #DCAE53  高价值服务、推荐标签、关键提醒
浅金背景       #FAF6EA  服务推荐和解释区域
主文字         #17231C
次文字         #6B756F
边框           #DCE2DC
风险红         #A44730  销售风险和错误，不作大面积装饰
成功绿         #2D7650
```

使用规则：

- 深绿和行动绿承载主品牌与主要操作；
- 暖金只用于服务推荐、阶段成就和高价值提醒；
- 风险红只标识真实风险或失败状态；
- 禁止同时使用多种高饱和强调色。

### 3.2 字体

中文优先使用系统无衬线字体：

```css
font-family: "Microsoft YaHei", "PingFang SC", system-ui, sans-serif;
```

字号层级：

- 页面主标题：28px / 1.25 / 700—800；
- 模块标题：20px / 1.35 / 700；
- 卡片标题：16px / 1.4 / 700；
- 正文：14px / 1.65 / 400；
- 辅助文字：12px / 1.6 / 400；
- 标签：11px / 1.3 / 700。

不依赖超细字重，保证平板和普通显示器可读性。

### 3.3 圆角、阴影和间距

- 页面卡片圆角：16px；
- 表单和子卡片圆角：10—12px；
- 胶囊标签：999px；
- 主卡片阴影：`0 7px 22px rgba(27,54,38,.045)`；
- 页面内容最大宽度：1440px；
- 桌面页边距：32—40px；
- 平板页边距：18—24px；
- 基础间距单位：4px，常用间距为8、12、16、24、32px。

## 4. 应用外壳

采用已确认的“A｜左侧工作台”布局。

### 4.1 桌面端

```text
230px固定左侧栏 + 自适应主内容区
```

左侧一级导航：

1. 老板工作台；
2. AI获客引擎；
3. AI销售教练；
4. 我的成果；
5. 陪跑服务；
6. 机构设置置于底部。

两个引擎必须同时可见，不折叠到“工具”或“工作流”之下。

### 4.2 平板横屏

- 左侧栏压缩到72—80px；
- 默认只显示图标，通过悬停、聚焦或点击显示名称；
- 主内容区保持卡片双列；
- 上传、继续诊断、查看报告等主要按钮触控高度不低于44px。

### 4.3 平板竖屏和窄屏

- 左侧栏转换为底部导航或抽屉；
- 双列内容变为单列；
- 统计卡片变为两列；
- 报告评分区置于正文上方；
- 表格优先转卡片，不强制横向缩放。

MVP不把手机端作为主要工作场景，但必须能完成登录、截图上传、音频上传和查看报告。

## 5. 老板工作台

### 5.1 首屏结构

```text
机构和身份
→ 个性化问候及当前建议
→ AI获客引擎、AI销售教练并列主卡
→ 自然产生的成果统计
→ 按优先级排列的下一步建议
```

### 5.2 双引擎主卡

AI获客引擎使用浅绿强调背景；AI销售教练使用白色卡片。两者尺寸一致，均包含：

- 简短价值说明；
- 典型使用场景；
- 唯一主按钮；
- 最近一次进度或结果。

不能把销售教练放到获客流程下方，也不能让15天计划成为首页主标题。

### 5.3 统计信息

只展示软件自然产生的数据：

- 已生成获客方案数；
- 已完成录音复盘数；
- 销售平均评分或变化；
- 待完成建议数。

不展示客户数、成交额等要求用户重复录入的数据。

## 6. AI获客引擎

### 6.1 引擎首页

顶部明确显示“AI获客引擎”独立名称和价值说明。页面包含：

- 新建获客项目；
- 最近或进行中的项目；
- 当前获客健康判断；
- 当前阶段行动计划；
- 按目标组织的入口。

按目标组织：

- 整体获客诊断；
- 抖音策略；
- 小红书策略；
- 短视频内容；
- 直播方案；
- 本地推建议；
- 招生和节点活动；
- 知识问答。

禁止以大量工具图标宫格作为首屏。

### 6.2 诊断输入

采用分步表单：

```text
机构和课程背景
→ 获客目标
→ 选择渠道
→ 上传截图或填写少量指标
→ 确认并开始诊断
```

必须标明：

- 哪些信息必填；
- 为什么需要该信息；
- 截图中可能包含的敏感信息；
- 预计分析步骤，而非虚假精确时长。

### 6.3 诊断报告

固定结构：

1. 核心结论；
2. 判断依据；
3. 问题优先级；
4. 建议策略；
5. 执行动作；
6. 所需素材；
7. 风险提醒；
8. 继续生成行动计划。

AI判断和用户输入使用不同视觉标签，避免把推断伪装成事实。

### 6.4 行动计划

- 展示阶段目标，不将15天写死；
- 允许选用15天模板；
- 每个动作显示目的、材料、完成标准和关联产出；
- 不建设复杂员工分配和任务协作。

## 7. AI销售教练

### 7.1 引擎首页

包含：

- 上传录音主入口；
- 新签和续费场景说明；
- 最近报告；
- 销售能力变化；
- 隐私和授权提示。

不展示员工日常待办或CRM销售阶段。

### 7.2 上传流程

```text
选择或填写销售对象标识
→ 选择场景或使用自动识别
→ 确认录音授权
→ 上传
→ 查看转写和分析进度
```

状态必须明确：等待中、转写中、分析中、需要确认、失败可重试、完成。

### 7.3 报告布局

桌面采用：

```text
左侧评分摘要（约320px） + 右侧证据和改进正文
```

平板竖屏改为上下布局。

报告顺序：

1. 总分、等级和一句结论；
2. 维度评分；
3. 最高成交风险；
4. 原话和时间戳；
5. 为什么有问题；
6. 替换话术；
7. 下次训练任务；
8. 历史变化。

每个扣分和风险必须尽可能关联原话。无法定位证据时显式标记，不能展示伪造引用。

## 8. 我的成果

页面只聚合自然产生的资产：

- 获客项目；
- 诊断报告；
- 内容、直播和活动方案；
- 销售分析报告；
- 训练任务；
- 评分变化；
- 顾问反馈。

支持按产品域、渠道、场景和时间筛选，不建设复杂文件管理器。

## 9. 陪跑服务与人工触达

### 9.1 服务页面

三类服务并列展示：

- 30天获客冲刺；
- 90天标准增长陪跑，作为默认主推；
- 创始人增长顾问计划。

每个服务展示：适合谁、解决什么、人工频率和明确边界。

### 9.2 上下文触达

推荐卡必须说明：

```text
AI发现了什么
→ 对经营可能有什么影响
→ AI已经完成什么
→ 真人顾问能继续解决什么
→ 为什么推荐该服务
```

触发位置：

- 获客报告末尾；
- 销售报告末尾；
- 工作台下一步建议；
- 陪跑服务页。

禁止：

- 无依据弹窗；
- 每次生成结果都强制销售；
- 故意隐藏AI可提供的完整建议；
- 用恐吓或虚假损失数字制造焦虑。

## 10. 核心组件

- `AppSidebar`：一级导航与机构入口；
- `EngineEntryCard`：双引擎主入口；
- `NextActionCard`：下一步建议；
- `AcquisitionProjectCard`：获客项目摘要；
- `DiagnosisSummary`：诊断结论和证据；
- `ActionPlanStep`：行动计划步骤；
- `FileUploader`：截图和音频上传；
- `AsyncTaskStatus`：异步任务状态；
- `ScoreSummary`：总分和等级；
- `DimensionScoreBar`：维度评分；
- `EvidenceQuote`：原话和时间戳；
- `ReplacementScript`：替换话术；
- `TrainingTaskCard`：训练任务；
- `ServiceRecommendation`：有依据的服务推荐；
- `EmptyState`、`ErrorState`、`NeedsReviewState`：统一状态组件。

组件状态至少包含默认、悬停、键盘聚焦、禁用、加载、成功和错误。

## 11. 交互与反馈

- 主要操作一次只保留一个主按钮；
- 异步任务离开页面后仍可恢复进度；
- 页面刷新不得丢失已创建任务；
- 高风险删除操作需要二次确认；
- 上传失败时保留表单上下文；
- 分析失败不得展示空白或虚假报告；
- 低置信度场景识别通过选择卡让老板确认；
- 长报告支持章节锚点，但不做复杂多层导航。

## 12. 可访问性与可读性

- 正文与背景对比度至少达到WCAG AA；
- 键盘操作有清晰焦点；
- 颜色不是状态的唯一表达方式；
- 图标配文字或可访问名称；
- 触控目标不小于44×44px；
- 报告图表提供文字结论；
- 不用小于12px的关键文本。

## 13. 页面验收

### 13.1 产品辨识

- 首屏5秒内能识别两个独立引擎；
- 不会误认为产品是CRM或教务系统；
- 不会误认为15天是软件固定周期。

### 13.2 老板使用效率

- 从工作台进入任一引擎不超过一次点击；
- 从销售教练首页开始上传不超过一次点击；
- 用户可以恢复上次项目和异步任务；
- 桌面和平板横屏均无需横向滚动完成核心操作。

### 13.3 服务触达

- 服务推荐能展示对应诊断或分析依据；
- 90天标准陪跑和创始人顾问服务边界清晰；
- 不用弹窗阻断核心报告阅读。

## 14. 已确认原型

可交互HTML原型：`prototype.html`。

原型覆盖：

- 老板工作台；
- AI获客引擎；
- AI销售教练报告；
- 我的成果；
- 陪跑服务。

原型用于确认信息架构和视觉方向，不代表最终接口已经实现。
