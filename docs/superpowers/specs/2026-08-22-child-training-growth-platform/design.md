# 儿童素质培训老板 AI 获客与销售训练平台设计规格

> 作者：Monkeycode  
> 设计日期：2026-08-22  
> 状态：已确认架构，待书面规格审阅

## 1. 产品定位

面向儿童素质培训机构老板、校长和市场负责人的 AI 获客与销售训练平台。

软件只聚焦两个结果：

1. 帮机构做好抖音、小红书等渠道获客策略与内容活动策划。
2. 帮机构发现并训练销售在新签、体测解读和续费沟通中的成交问题。

软件不是 CRM、会员系统、教务系统或完整经营管理系统。

## 2. 已确认边界

### 2.1 核心用户

- 第一核心用户：机构老板、校长、市场负责人。
- 陪跑顾问：使用顾问后台查看机构摘要和服务节点。
- 员工：不是第一阶段核心用户，不建设员工工作台；录音可由老板上传，后续预留一次性上传入口。

### 2.2 明确不做

第一阶段不建设：

- 客资明细、客资分配、邀约跟进和 CRM 管道；
- 会员档案、排课、消课、教务和考勤；
- 销售提成、完整订单和财务核算；
- 要求机构重复录入已有会员系统数据；
- 多行业泛化版本；
- 复杂顾问排班、聊天、工单和会议系统。

获客复盘只接收少量汇总指标或截图，不保存具体客户档案。

### 2.3 周期

- 软件长期使用，不绑定 15 天。
- 15 天仅作为抖音/小红书运营的可选行动模板。
- 30 天获客冲刺是短期服务产品。
- 90 天标准增长陪跑是核心服务产品。
- 创始人增长顾问计划处理高价值、非标准经营问题。

## 3. 产品信息架构

```text
老板工作台
├─ AI获客引擎
├─ AI销售教练
├─ 我的成果
├─ 陪跑服务
└─ 机构设置
```

### 3.1 工作台

工作台不展示复杂 CRM 漏斗，回答四个问题：

- 当前想解决什么问题？
- 上次做到哪里？
- AI发现了什么问题？
- 下一步建议做什么？

两个核心入口必须并列、独立展示：

- 我要获得更多客资；
- 我要提高销售成交。

### 3.2 AI获客引擎

独立入口、独立首页、独立价值说明、独立结果报告。

功能范围：

- 抖音账号与来客诊断；
- 小红书账号与内容诊断；
- 短视频选题、脚本、标题和发布建议；
- 直播策划与复盘；
- 本地推和平台运营建议；
- 公开课、赛事、体验课和节点活动策划；
- 平台截图和数据表分析；
- 获客知识库问答；
- 获客项目、阶段计划和行动建议；
- 阶段复盘。

每次输出统一包含：

```text
判断依据 → 建议策略 → 执行动作 → 所需素材 → 风险提醒
```

### 3.3 AI销售教练

功能范围：

- 新签实操录音复盘；
- 续费沟通录音复盘；
- 第二期增加体测解读和内部演练；
- 音频上传、格式校验和转写；
- 场景识别与人工确认；
- 结构化评分；
- 原话证据和时间戳；
- 替换话术；
- 训练任务；
- 历史评分纵向对比。

报告必须包含：

- 总分和等级；
- 各维度评分；
- 原话证据；
- 主要问题和成交风险；
- 替换话术；
- 下次训练任务；
- Skill、评分规则和模型版本。

### 3.4 我的成果

沉淀诊断、获客方案、内容方案、截图分析、录音报告、训练任务、评分趋势和顾问反馈。用户不需要额外维护复杂档案。

### 3.5 陪跑服务

展示并承接三类服务：

- 30天获客冲刺；
- 90天标准增长陪跑；
- 创始人增长顾问计划。

## 5. 核心数据模型

### 5.1 机构域

```text
organizations
organization_members
institution_locations
```

机构成员角色：`owner`、`principal`、`marketing_lead`、`advisor`、`platform_admin`。

MVP界面默认单机构，但数据模型支持一个用户管理多个机构或校区。

### 5.2 获客域

```text
acquisition_projects
acquisition_channels
acquisition_diagnoses
acquisition_action_plans
acquisition_snapshots
acquisition_assets
```

`acquisition_projects` 是长期获客容器，可持续数月；15天计划是项目下的可选模板。`acquisition_snapshots` 只保存汇总指标，不保存客户明细。

### 5.3 销售教练域

```text
sales_recordings
transcription_jobs
sales_analyses
sales_evidence
training_tasks
sales_score_snapshots
```

录音与场景、机构、分析版本关联。销售人员可以作为被分析对象或匿名编号，不要求其成为平台用户。

### 5.4 服务域

```text
service_programs
service_touchpoints
service_alerts
consultant_notes
```

90天标准陪跑生成启动、第30天、第60天、第90天四个正式沟通节点；系统每周检查，异常触发人工介入。

### 5.5 异步与AI运行域

```text
async_tasks
ai_runs
```

用于OCR、转写、场景识别、评分、报告生成和服务周检。每个任务必须有幂等键、状态、重试次数、错误码和关联资源。

## 6. 关键数据流

### 6.1 获客引擎

```text
选择机构
→ 创建或进入获客项目
→ 选择渠道
→ 上传截图或填写少量指标
→ 创建诊断任务
→ 知识库检索与AI诊断
→ 返回证据、问题优先级和策略
→ 生成阶段行动计划
→ 老板执行
→ 上传阶段结果
→ AI复盘
→ 生成下一阶段建议
→ 沉淀到我的成果
```

结果必须区分用户输入、系统计算、AI判断、引用依据、建议动作和人工确认事项。

### 6.2 销售教练

```text
老板选择场景
→ 上传录音
→ 文件校验和授权确认
→ 私有对象存储
→ 异步转写
→ 场景识别
→ 选择销售Skill
→ 结构化评分
→ 原话证据
→ 替换话术
→ 训练任务
→ 历史能力对比
```

场景识别置信度低时，必须允许手动确认；转写成功但评分失败时，保留转写并允许单独重跑评分。

## 7. AI、知识库与Skill配置化

`E:\程序开发\自创skill\追光小牛` 中的Skill作为方法论来源，不直接作为业务代码硬编码依赖。

Skill运行配置至少包含：

```text
skill_code
version
input_schema
output_schema
scoring_dimensions
knowledge_scopes
brand_config
fallback_strategy
```

建议知识检索上下文为：

```text
行业 + 产品域 + 渠道 + 场景 + Skill版本
```

品牌配置集中管理：

- 品牌名称；
- 课程与产品术语；
- 推荐表达；
- 禁用词；
- 报告语气；
- 服务产品说明；
- 合规边界。

统一AI运行器负责：

```text
读取Skill
→ 读取品牌配置
→ 检索知识库
→ 脱敏组装上下文
→ 调用模型
→ JSON Schema校验
→ 重试、降级或人工复核
→ 保存ai_runs
```

## 8. 人工服务触达

不通过高频弹窗销售，而通过诊断结果、使用行为和成果报告触达。

### 8.1 触发场景

- 获客诊断显示渠道策略混乱；
- 多次生成方案但执行中断；
- 截图数据持续异常；
- 新签录音连续低分；
- 续费沟通缺少成果回顾；
- 多个销售出现同一问题；
- 课包、活动、人效或坪效问题超出软件范围。

### 8.2 触达内容

```text
AI识别的问题
→ 对经营可能造成的影响
→ AI可以立即解决的部分
→ 真人顾问可继续解决的部分
→ 推荐服务产品
```

### 8.3 顾问后台最小范围

- 机构列表；
- 机构详情；
- 获客项目概览；
- 销售训练重点报告；
- 服务状态和触达节点；
- 异常列表；
- 顾问记录；
- 阶段总结。

不做通用CRM、复杂工单和排班系统。

## 9. 权限、隐私与失败处理

### 9.1 权限

- 所有数据按机构隔离；
- 后端验证成员关系；
- 顾问只能访问被分配机构；
- 会员等级不代表管理员身份；
- 服务权益与顾问查看权限分离；
- 关键读取和操作写审计日志。

### 9.2 录音隐私

- 原始音频存放私有对象存储；
- 数据库只保存对象引用和元数据；
- 播放使用短时签名URL；
- 上传前确认录音授权；
- 原始音频默认保留90天；
- 转写和结构化报告可长期保留；
- 用户可提前删除；
- 日志不记录完整音频、转写和敏感原话；
- 尽量不将儿童姓名、手机号等信息发送给AI。

### 9.3 异步状态

```text
queued
processing
succeeded
failed_retryable
failed_final
needs_review
cancelled
```

AI、ASR或OCR失败时不能伪造成功报告。支持有限重试、备用模型、单阶段重跑和用户可见的处理中状态。

## 11. 验收指标

### 产品使用

- 机构建档完成率；
- 首次获客诊断完成率；
- 首次销售录音分析完成率；
- 7日和30日回访率；
- 获客项目持续使用率；
- 服务项目续购率。

### 获客引擎

- 诊断和方案生成成功率；
- 截图解析成功率；
- 建议保存或采纳比例；
- 阶段复盘完成率；
- 用户对诊断准确性的评价。

### 销售教练

- 音频上传和转写成功率；
- 场景识别准确率；
- 原话证据定位准确率；
- 报告结构完整率；
- 训练任务完成率；
- 连续上传率；
- 关键维度纵向改善幅度。

### 服务与安全

- 启动及30/60/90天沟通完成率；
- 异常处理及时率；
- 服务续约率；
- 机构越权访问测试全部通过；
- 未授权录音无法下载；
- 异步任务重复执行不产生重复结果；
- 敏感数据不进入普通日志。

## 12. 实施顺序

1. 机构和权限基础；
2. 私有文件存储和异步任务；
3. 获客项目模型；
4. 迁移抖音/小红书诊断与计划；
5. 销售录音最小闭环；
6. Skill和知识库版本化；
7. 陪跑顾问最小后台；
8. PWA和成果趋势优化。

## 13. 已确认的MVP决策

- MVP销售场景：新签实操＋续费沟通；
- 原始录音默认保留90天，转写和结构化报告可长期保留；
- 数据模型支持一用户多机构，MVP界面默认单机构；
- 软件长期使用；
- 30天、90天和创始人顾问服务分层售卖；
- 获客引擎和销售教练为两个独立产品入口；
- 老板是核心用户，员工不承担日常系统使用。

前端视觉方向、布局、页面结构、组件、响应式和服务触达规范见：
