# 少儿体育机构7天获客到成交闭环设计

> 作者：Monkeycode  
> 日期：2026-08-23  
> 范围：构造匿名样本验证与老板端第一版业务闭环，不接入追光小牛真实数据。

## 1. 目标与边界

### 目标

让少儿体育培训机构老板在不理解知识库和 AI 的情况下，用不超过 3 分钟填写最小经营数据，得到一个有证据的主问题、1—2 个七天行动，并在下一周期提交结果完成复盘。

### 第一版范围

- 主闭环：获客 → 预约/到店 → 体验课 → 正价成交。
- 首批输入：结构化表单，不做语音和 OCR。
- 首批验证：四类匿名样本：获客不足、预约到店不足、到店不成交、成交后续费不足。
- 知识范围：获客漏斗、内容、体验课、投流实验、销售承接和续费规则。
- 不包含：CRM 明细、儿童个人信息、自动投放、支付、生产 LLM 供应商配置。

## 2. 用户流程

1. 用户选择本周最想解决的问题：咨询少、预约少、到店少、成交少、续费差或不知道问题。
2. 用户填写机构课程、目标家长和最小聚合指标；字段允许为空并说明缺失影响。
3. 系统根据问题类型映射 Skill 和知识检索维度，不要求用户选择知识库、Skill 或渠道技术参数。
4. 系统生成诊断卡：一个主问题、数据证据、知识依据、排除项、1—2 个七天行动、验证指标、停止条件和人工复核状态。
5. 用户从诊断卡进入行动计划，确认负责人和截止日期。
6. 用户在七天后填写新一周期聚合指标并标记行动完成情况。
7. 系统比较前后数据，输出继续、调整、停止或顾问介入之一。

## 3. 最小数据模型

### 首次诊断输入

- `problem_code`：目标问题枚举；
- `course_name`、`age_range`、`city`：课程与基本场景；
- `views`、`valid_leads`、`appointments`、`arrivals`、`trial_completed`、`new_sales`、`renewals`、`eligible_renewals`、`spend`：聚合指标；
- `content_note`、`sales_note`、`delivery_note`：可选短描述；
- 不接收儿童姓名、电话、完整 CRM 明细。

### 诊断输出

固定包含：

- `primaryIssue`；
- `evidence`；
- `basis` / `knowledgeStatus`；
- `excludedActions`；
- `actions`；
- `validationMetrics`；
- `stopConditions`；
- `needs_review`。

### 复盘输入与输出

复盘输入复用同一组聚合指标，并增加行动完成状态。输出 `continue`、`adjust`、`stop`、`consultant` 四选一，附数据变化和理由。

## 4. 知识与诊断策略

- 获客不足：优先检索漏斗、内容行动卡和体验产品规则；禁止无依据扩大投流。
- 预约/到店不足：优先检查咨询承接、预约动作、地点/时间/适龄信息和体验课承接。
- 到店不成交：优先检查体验过程、教练反馈、课程适配、价格梯度和销售承接。
- 续费不足：切换到教学交付、成长反馈、出勤、家长沟通和续费规则。
- 每次输出最多一个主问题和两个优先动作；不同问题必须产生不同诊断方向。
- 知识检索结果记录知识 ID、证据级别、核验日期和是否需要复核。
- LLM 未配置或输出不符合契约时，保持 `needs_review`，不伪造成功。

## 5. 前端设计原则

- 用业务问题替代技术参数入口。
- 首屏只显示必要字段；高级指标折叠。
- 对每个空字段说明“不填写会影响什么”，但允许继续。
- 诊断卡优先显示“现在先做什么”，依据和细节随后展开。
- 行动计划支持确认负责人、截止日期、完成状态和结果备注。
- 复盘页显示前后指标变化，不只显示历史文本。
- 所有错误、待人工复核和数据不足状态明确可见。

## 6. 验证方案

### 样本

1. 有曝光但有效咨询少；
2. 有效咨询多但预约/到店少；
3. 到店和体验正常但正价成交为零；
4. 新签正常但续费低。

### 验收指标

- 首次输入步骤不超过 3 分钟的操作路径；
- 四类样本主问题与预期一致；
- 每个样本至少命中两条相关知识；
- 诊断证据来自聚合数据且计算正确；
- 每个样本输出 1—2 个具体行动、指标和停止条件；
- 复盘能根据数据变化选择继续/调整/停止/顾问；
- 缺失指标不生成虚假比率；
- 敏感字段不进入 Runner 上下文；
- 无 LLM 时显示待人工复核；
- 后端专项、全量回归和前端构建通过。

## 7. 风险与降级

- 当前环境没有真实 LLM 时，使用结构化规则和契约测试验证链路，但不宣称验证了模型生成质量。
- 当前 MySQL 不可用时使用 Mock DB；必须保留 MySQL 查询兼容性。
- 没有足够指标时输出数据不足，并要求下一周期补录，不强行判断。
- 高风险隐私、投流或冲突知识进入人工复核，不自动给出强制动作。

## 8. 分阶段交付

### 阶段一：测试资产

构造四类匿名样本和闭环验收脚本，先证明不同输入得到不同且合理的结果。

### 阶段二：老板端输入

将固定项目/固定诊断文本替换为问题选择和最小数据表单，保存输入快照。

### 阶段三：诊断到行动

展示证据和知识依据，支持一键保存七天行动计划及负责人/截止日期。

### 阶段四：复盘

录入下一周期数据，比较变化并输出四态建议及顾问升级。

阶段二至四不扩展 CRM、支付或语音/OCR。
