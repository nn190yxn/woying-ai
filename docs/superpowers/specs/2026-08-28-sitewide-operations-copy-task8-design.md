# 我赢AI全站运营语言任务8设计：长尾页面与运行时文案治理

> 作者：Monkeycode  
> 日期：2026-08-28  
> 状态：已确认（按任务7后续计划执行）

## 1. 目标

清理任务7后扫描剩余的客户侧长尾技术口吻，使小红书、私域、通用工具、计算器、表格模板和运行时错误提示统一回到儿童素质培训机构经营语境。保留现有路由、组件、接口、字段、公式、权限和历史数据兼容，不扩大产品范围。

## 2. 范围

### 2.1 纳入

1. 小红书、私域和通用工具公开入口、标题、返回按钮、卡片说明和升级引导。
2. 计算器与表格模板的页面标题、输入说明、结果解释和行动按钮。
3. 后端路由、服务、规则模板中直接返回给用户的标题、建议、状态和错误文字。
4. 路由兜底、未知入口、网络错误和第三方服务失败的用户提示。
5. 运营语言扫描脚本、专项测试和任务文档，使扫描结果可定位、可回归。

### 2.2 不纳入

- 不修改数据库结构、历史数据、API URL、JSON 字段、内部枚举或组件文件名。
- 不删除餐饮、美业等既有实现，只保持客户侧入口按第一阶段儿童培训聚焦。
- 不修改技术设置区、日志内部字段或仅供开发者阅读的注释，除非其内容会直接进入客户页面或接口响应。
- 不引入新的模型、供应商、权限角色或营销承诺。

## 3. 语言规则

- “智能体/Agent/矩阵/生成器/分析器”在客户入口按经营问题和动作命名；内部代码标识保持不变。
- 指标保留计算口径，首次出现补充中文业务解释；不改变公式。
- 错误消息只说明当前动作、影响和下一步；原始技术错误仅进入已脱敏日志。
- 无数据、规则兜底、模型生成和顾问确认状态必须区分，不承诺自动获客、精准诊断或确定结果。
- 任务8仅处理扫描命中和其直接上下文，避免机械全局替换造成业务语义错误。

## 4. 实施顺序

1. 先处理小红书、私域、通用入口和高频返回按钮。
2. 再处理计算器与表格模板的标题和结果说明。
3. 再处理后端用户可见返回文案与第三方错误映射。
4. 最后补全扫描豁免边界、属性测试和兼容回归。

每一批修改后运行对应专项测试；不通过时只修复本批相关问题。

## 5. 测试与验收

- 公开前端扫描不再命中任务定义的禁用技术词；技术设置区允许白名单术语。
- 后端用户可见样本不包含原始第三方错误、堆栈、密钥、Token、手机号或完整用户输入。
- 核心小红书、私域、工具和计算器接口字段与路由保持不变。
- 既有运营语言专项、核心业务回归和前端生产构建通过。
- 最终记录剩余扫描项及理由；若仍有内容属于技术设置或内部实现，明确归档，不借任务8扩大范围。

## 6. 风险与控制

- 批量改名可能破坏路由或测试：只修改展示字符串，不改 code/path/key。
- 技术词可能出现在客户错误分支：覆盖正常、空数据、失败和兜底分支测试。
- 长文案可能造成布局问题：任务8只做必要文案长度控制，全面响应式检查留给后续质量门禁任务10。
